ExecPlan: Move Saved Data From Gson Reflection To Compile-Time Serialization

When this is complete, saved data no longer depends on R8 keeping field names or on Gson creating objects by reflection. Every durable file, Room payload, and export is read and written by serializers the compiler generates, an offline copy survives any app update, and the hand-maintained R8 contract machinery is deleted. Users see no format loss: every file written by an older build still loads, except three formats retired under the two-release rule in AGENTS.md (the pre-v0.8.0 whole-file stores, version 2 offline manifests, and the version 1 statistics file).

Purpose / Big Picture

Gson fills Kotlin objects by reflection. That bypasses constructors and Kotlin null safety, and it means R8 (the release shrinker and obfuscator) can break saved data by renaming a field. The project guards against this with about 280 lines of keep rules, a 59-class contract list, a Python verifier, and a Gradle task. kotlinx.serialization generates each serializer at compile time, so field names are ordinary strings in generated code and most of that machinery can go.

The guard already has a hole. Offline manifests serialize the domain Post directly, and Post is not in the keep rules, so release builds write keys such as a and b. Phase 1 closes that hole on its own, before any new library arrives.

How to see it working: after an update, offline collections remain available; a release-build manifest.json shows readable keys such as sourcePostId; and app/proguard-rules.pro no longer lists durable records.

Context And Orientation

Terms: a record is a Kotlin class that exists only to define a stored JSON shape. A surface is one place JSON is persisted or exchanged. Unsafe allocation is how Gson creates a class with no zero-argument constructor: it skips the constructor, so Kotlin defaults do not run and non-null fields can hold null. The tree API is Gson's JsonObject/JsonParser, which uses no reflection.

Every store defaults to a plain Gson(). That means nulls are omitted, defaulted values are written, < > & = ' are escaped as < and friends, unknown keys are ignored, and reads are lenient.

Compatibility Contract

Every phase must honor these. They come from reading what each consumer actually requires.

// One shared configuration, defined once in Phase 2.
val DurableJson = Json {
    ignoreUnknownKeys = true   // Newer files and retired fields must not be rejected.
    encodeDefaults = true      // validateBackupSettings requires defaulted keys to be present.
    explicitNulls = false      // LocalPostPayloadCodec.validateCurrentShape treats a present key as data.
    coerceInputValues = true   // A stored null on a defaulted field repairs instead of resetting the store.
    isLenient = true           // Gson accepted "5" as Int and "true" as Boolean.
}
Failure types are part of the format. SerializationException extends IllegalArgumentException. AtomicJsonFileStore must quarantine on SerializationException only; a plain IllegalArgumentException from an adapter must keep propagating, as AtomicJsonFileStoreTest pins. CredentialEnvelopeStore.toCredentialReadFailure must add SerializationException to the ReconnectRequired path, or a corrupt envelope is stuck on "temporarily unavailable" forever.
RuleWhy
Keep enum-like fields as StringUnknown values are tolerated today. A kotlinx enum would throw and reset the store.
Keep explicit @SerialName on every propertyA property rename must not silently change a stored key.
Do not annotate core-domain classesStorage records already mirror them, and the domain stays free of format concerns.
Compare decoded values in SharedPostPayloadWriterkotlinx does not HTML-escape, so the same post encodes to different bytes than Gson wrote. Comparing strings would rewrite every old row once for nothing.
Use kotlinx Transient on CodexShareImageRef.localPathkotlin.jvm.Transient is ignored by kotlinx, which would export device paths.
Never put SourceKey in a @Serializable typeIt is a value class with a private constructor. Records use String ids.

Phases

Each phase is one PR that leaves the app shippable. Phases 1 to 3 ran from lowest to highest data risk, so the harness proved itself before it guards irreplaceable data.

The remaining phases run in dependency order, in parallel where they do not share records: Phase 8 (now a deletion) and Phase 7 first; then Phase 4 and Phase 5, which no longer have to carry the importers' records; then Phase 6, whose backup leaves are the records Phases 4 and 5 convert; then Phase 9.

Work Plan

  2. Each later phase: capture golden files first and commit them, convert records from @field:SerializedName("x") to @SerialName("x") with @Serializable, switch the entry points, then remove that phase's classes from the keep rules and contract list.
  3. Convert a record and its nested records together. Keep gson on the test classpath of every module so the parity harness still runs after production stops using reflection.
  4. Update .docs/DEVELOPMENT.md in the phase that makes its current Gson sentences false.

Surprises And Discoveries

  • Observation: release manifests already use obfuscated keys. Evidence: app/build/outputs/mapping/release/mapping.txt maps Post.id to a and preview to b, and Post has no keep rule.
  • Observation: an undecodable manifest is treated as "no copy", so OfflineMediaStore.commit deletes the old generation and forgets other collections' ownership. Evidence: readRecord returns null through runCatching, then commit writes setOf(owner).
  • Observation: the existing golden tests use serializeNulls(), which production does not, so they do not pin real output. Evidence: GsonWireContractTest.kt:12.
  • Observation: nine keep-rule entries refer to classes that no longer exist, and five records are unused. Evidence: app/proguard-rules.pro keeps SettingsStoreFile and CodexStoreFile, which no longer exist, and nothing in production references UiRestoreStoreFile or LikesStoreFile.
  • Observation: the local theoria-search-test emulator stayed adb-offline for over seven minutes on 2026-11-08 and device_open failed. Evidence: adb devices reported emulator-5554 offline. CI emulators passed the same day.
  • Observation: PostStorageCodec.decode is not a strict inverse of encode (it trims taxonomy values and can add recovered Pixiv translations). Evidence: PostStorageRecords.kt. Harmless for manifests, since stored posts already go through it, and ordinary posts round-trip equal in OfflineMediaStoreTest.
  • Observation: reflective v2 reads cannot work on any release build. Evidence: the minified acceptance run returned no record for a valid v2 manifest, and dexdump -a shows no Signature annotation on Post in the acceptance APK or the shipped v1.3.0 APK, so Gson decodes media as raw maps and the first ImageRef access throws inside runCatching. Offline copies therefore could not be read back in release builds until this phase.
  • Observation: the acceptance fixture writes whichever names R8 assigns in the current build, while the reader table is frozen. Evidence: ReleaseDataAcceptanceActivity.writeLegacyOfflineManifest. If Post fields change before Phase 9 removes v2 support, replace that fixture with literal shipped keys.

Evidence: core-data/src/test/resources/golden/backup/backup-v2.json. Phase 6 must not assume escaped input.

  • Decision: use PostStorageRecord for manifest v3 instead of annotating domain classes. Rationale: it is already the stable, tested mirror of Post, and no new library is needed. Date/Author: 2026-11-08 / Claude.
  • Decision: read v2 manifests by hand from the JSON tree with a frozen table of shipped key names. Rationale: the first approach, reusing the reflective reader, failed the minified acceptance run because R8 strips generic signatures from Post. The tree reader needs no reflection and no longer constrains changes to the domain classes. Date/Author: 2026-11-08 / Claude.
  • Decision: use kotlinx.serialization rather than Moshi. Rationale: code generation is built into the Kotlin compiler toolchain, and its JSON tree is available if Gson's tree use is ever replaced. Date/Author: 2026-11-08 / Claude.
  • Decision: use kotlinx-serialization-json 1.13.0 instead of the planned 1.12.0. Rationale: it is current and works with Kotlin 2.4.21. Date/Author: 2026-11-18 / Claude.

Rationale: production Gson still reads and writes them, and the R8 keep rules match on @SerializedName; removing it early would let R8 rename stored keys. The phase that switches the store drops the Gson names and the keep rules together. Date/Author: 2026-11-18 / Claude.
  • Decision: assertGsonParity also requires the samples, together, to emit every property path the descriptor declares (map contents and recursive types excepted). Outcomes And Retrospective

Phase 1: offline manifests write v3 with stable keys and upgrade readable v2 copies; shipped in v1.4.0.

Phase 2: promoted. kotlinx-serialization-json 1.13.0 runs beside Gson with no store changes. The prototype serializer survives R8 on API 36 and 37 and agrees with Gson in both directions. The parity harness catches renamed keys and unexercised properties. Golden files for every remaining surface are committed. Lesson for later phases: write samples that set every nullable property, because the harness rejects anything less, and that rule caught a gap in the first prototype test.

Phase 3: the storage engine takes kotlinx serializers, and five low-risk stores moved with no change to what older files load into. 13 records left the R8 keep rules. Lesson: Detekt's analysis cannot see plugin-generated serializer() companions in core-sources and reports the following code as unreachable; the reified encodeToString/decodeFromString calls compile to the same serializer and avoid it.

Phase 8: the legacy import path is deleted rather than ported, which removed about 3,400 lines and let Phases 4 to 6 skip the importers' records. Lesson: before migrating code, check whether the rule that kept it alive still holds.

Phase 7: credentials and the statistics share file moved with old files decoding identically and corrupt envelopes still asking for reconnection. Lesson: capture goldens from real production output, not hand-written fixtures; the real envelope showed escaping a hand-written one would have missed.

Phase 5: the Room payloads moved with no rewrite of existing rows and no schema change. Lesson: when a codec's output bytes change, decide whether a value changed by comparing decoded values, never stored strings.

Phase 4: the four DataStore files moved onto one serializer with shipped files loading to the same values, and three latent crashes became repairs. Lesson: check the schema on the raw JSON before any typed decode, and after resolving conflicts in a list of rules, diff the result against main instead of trusting the conflict view.

Phase 9, part 1: the v2 manifest reader and its frozen key table are gone and manifests are a single record. Lesson: when a test exists to pin one guard, change only what that guard checks; a mutation run showed a mixed test passing for the wrong reason.

Phase 6: backups, the restore journal, the developer copy and pinned searches moved, and with them the last reflective Gson in shipped code. Lesson: when porting error paths, pin the exception type the user-facing code branches on, not only the message.

Phase 9: the R8 contract verifier, keep rules and Gson parity harness are deleted. Stored formats are now guarded by golden files checked for completeness, the minified acceptance run, and explicit @SerialName on every property. Lesson: a guard that compares against the thing being replaced stops proving anything once the replacement ships; keep the rule it enforced and point it at real files.

Phase 10: Gson is gone from app and core-data, so reflective decoding of saved data cannot compile there and the storage engine has one API. Lesson: prefer API forms that static analysis can resolve without compiler plugins.

Overall: across PRs #150 to #160 shipped sources shrank by roughly 2,200 lines net, and the hand-kept R8 contract (about 280 lines of keep rules, a 59-class list, a Python verifier and a Gradle task) no longer exists. The largest single simplification was not in the original plan: deleting the legacy importers instead of porting them. Running phases in parallel worked because each owned its records and the plan file had one owner; the one near-miss was a rebase that dropped live keep rules, caught only by the minified CI run. A whole-result review by a reader who wrote none of it found defects every per-phase review had passed.

Follow-ups left open:

  • Drop the unused migration_metadata and recents_migration_metadata tables and their two entities at the next Room schema change.
  • DataStore's corrupt-file copy overwrites the previous .corrupt file and the store resets even when the copy fails; the custom-sites store ignores the result. The atomic file stores already keep distinct, verified copies.
  • A folder whose offline manifest cannot be read is never cleaned up when a collection is removed.
  • Regenerate the baseline and startup profiles, which still name deleted and Gson-era methods.
  • Port the Hitomi parser in core-sources off Gson so app's device tests can drop the dependency. The rest of provider parsing stays on Gson.
  • mergeSparsePost drops a stored contentHash when the incoming snapshot has none, and Post.contentHash's KDoc calls it live-only data although it is stored.
  • parseLegacyProfileId and the activeProfile settings field date from v0.6.0; old backups can still carry them, so they were left.

Idempotence And Recovery

Build and test commands are safe to rerun. Each phase is a separate PR, so a bad phase reverts on its own. Reading always accepts the old format, so an app reverted to a phase's predecessor still needs that format to be readable: phases 3 to 8 keep Gson-readable output (same keys, nulls omitted, defaults present) so a rollback does not strand data. Manifest v3 is the exception. Older builds ignore it and see no offline copy, so its downloads remain on disk but are offered again as downloads. Android blocks version downgrades on the signed update path, so this only affects manual rollbacks.

Device work uses isolated packages only (com.theoriacodex.acceptance, com.theoriacodex.debug). Never touch com.theoriacodex.
