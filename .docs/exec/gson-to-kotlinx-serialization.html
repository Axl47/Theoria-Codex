ExecPlan: Move Saved Data From Gson Reflection To Compile-Time Serialization

When this is complete, saved data no longer depends on R8 keeping field names or on Gson creating objects by reflection. Every durable file, Room payload, and export is read and written by serializers the compiler generates, an offline copy survives any app update, and the hand-maintained R8 contract machinery is deleted. Users see no format loss: every file written by an older build still loads.

Purpose / Big Picture

Gson fills Kotlin objects by reflection. That bypasses constructors and Kotlin null safety, and it means R8 (the release shrinker and obfuscator) can break saved data by renaming a field. The project guards against this with about 280 lines of keep rules, a 59-class contract list, a Python verifier, and a Gradle task. kotlinx.serialization generates each serializer at compile time, so field names are ordinary strings in generated code and most of that machinery can go.

The guard already has a hole. Offline manifests serialize the domain Post directly, and Post is not in the keep rules, so release builds write keys such as a and b. Phase 1 closes that hole on its own, before any new library arrives.

How to see it working: after an update, offline collections remain available; a release-build manifest.json shows readable keys such as sourcePostId; and app/proguard-rules.pro no longer lists durable records.

Context And Orientation

Terms: a record is a Kotlin class that exists only to define a stored JSON shape. A surface is one place JSON is persisted or exchanged. Unsafe allocation is how Gson creates a class with no zero-argument constructor: it skips the constructor, so Kotlin defaults do not run and non-null fields can hold null. The tree API is Gson's JsonObject/JsonParser, which uses no reflection.

Every store defaults to a plain Gson(). That means nulls are omitted, defaulted values are written, < > & = ' are escaped as < and friends, unknown keys are ignored, and reads are lenient.

Compatibility Contract

Every phase must honor these. They come from reading what each consumer actually requires.

// One shared configuration, defined once in Phase 2.
val DurableJson = Json {
    ignoreUnknownKeys = true   // Newer files and retired fields must not be rejected.
    encodeDefaults = true      // validateBackupSettings requires defaulted keys to be present.
    explicitNulls = false      // LocalPostPayloadCodec.validateCurrentShape treats a present key as data.
    coerceInputValues = true   // A stored null on a defaulted field repairs instead of resetting the store.
    isLenient = true           // Gson accepted "5" as Int and "true" as Boolean.
}
Failure types are part of the format. SerializationException extends IllegalArgumentException. AtomicJsonFileStore must quarantine on SerializationException only; a plain IllegalArgumentException from an adapter must keep propagating, as AtomicJsonFileStoreTest pins. CredentialEnvelopeStore.toCredentialReadFailure must add SerializationException to the ReconnectRequired path, or a corrupt envelope is stuck on "temporarily unavailable" forever.
RuleWhy
Keep enum-like fields as StringUnknown values are tolerated today. A kotlinx enum would throw and reset the store.
Keep explicit @SerialName on every propertyA property rename must not silently change a stored key.
Do not annotate core-domain classesStorage records already mirror them, and the domain stays free of format concerns.
Freeze RoomRecentsLegacyImporter.destinationSummary on GsonThe only output that must stay byte-identical: its hash is compared on every launch while a migration is unarchived. It reflects only strings, longs, and null, so it needs no keep rules.
Compare decoded values in SharedPostPayloadWriterComparing strings would rewrite every old row once, which changes bytes hashed by unarchived migration proofs.
Use kotlinx Transient on CodexShareImageRef.localPathkotlin.jvm.Transient is ignored by kotlinx, which would export device paths.
Never put SourceKey in a @Serializable typeIt is a value class with a private constructor. Records use String ids.

Phases

Each phase is one PR that leaves the app shippable. Phase order runs from lowest to highest data risk, so the harness has proven itself before it guards irreplaceable data.

Surprises And Discoveries

  • Observation: release manifests already use obfuscated keys. Evidence: app/build/outputs/mapping/release/mapping.txt maps Post.id to a and preview to b, and Post has no keep rule.
  • Observation: an undecodable manifest is treated as "no copy", so OfflineMediaStore.commit deletes the old generation and forgets other collections' ownership. Evidence: readRecord returns null through runCatching, then commit writes setOf(owner).
  • Observation: the existing golden tests use serializeNulls(), which production does not, so they do not pin real output. Evidence: GsonWireContractTest.kt:12.
  • Observation: nine keep-rule entries refer to classes that no longer exist, and five records are unused. Evidence: app/proguard-rules.pro keeps SettingsStoreFile and CodexStoreFile, which no longer exist, and nothing in production references UiRestoreStoreFile or LikesStoreFile.
  • Observation: the local theoria-search-test emulator stayed adb-offline for over seven minutes on 2026-11-08 and device_open failed. Evidence: adb devices reported emulator-5554 offline. CI emulators passed the same day.
  • Observation: PostStorageCodec.decode is not a strict inverse of encode (it trims taxonomy values and can add recovered Pixiv translations). Evidence: PostStorageRecords.kt. Harmless for manifests, since stored posts already go through it, and ordinary posts round-trip equal in OfflineMediaStoreTest.
  • Observation: a v2 rewrite that throws inside readRecord must not hide a readable copy. Evidence: found in review and pinned by a version 2 manifest that cannot be rewritten stays available and upgrades later.

Decision Log

  • Decision: migrate reflective surfaces only and keep Gson's tree API. Rationale: the tree API has no reflection or R8 exposure, and rewriting about 190 provider parsing sites adds risk with no safety gain. Date/Author: 2026-11-08 / Claude.
  • Decision: use PostStorageRecord for manifest v3 instead of annotating domain classes. Rationale: it is already the stable, tested mirror of Post, and no new library is needed. Date/Author: 2026-11-08 / Claude.
  • Decision: upgrade v2 manifests through the existing reflective reader. Rationale: the mapping comparison shows names are unchanged since v1.3.0, so this is the simplest correct reader. Date/Author: 2026-11-08 / Claude.
  • Decision: use kotlinx.serialization rather than Moshi. Rationale: code generation is built into the Kotlin compiler toolchain, and its JSON tree is available if Gson's tree use is ever replaced. Date/Author: 2026-11-08 / Claude.
  • Decision: do not delete legacy importers. Rationale: it cannot be shown that every install has finished archiving them. Date/Author: 2026-11-08 / Claude.

Idempotence And Recovery

Build and test commands are safe to rerun. Each phase is a separate PR, so a bad phase reverts on its own. Reading always accepts the old format, so an app reverted to a phase's predecessor still needs that format to be readable: phases 3 to 8 keep Gson-readable output (same keys, nulls omitted, defaults present) so a rollback does not strand data. Manifest v3 is the exception. Older builds ignore it and see no offline copy, so its downloads remain on disk but are offered again as downloads. Android blocks version downgrades on the signed update path, so this only affects manual rollbacks.

Device work uses isolated packages only (com.theoriacodex.acceptance, com.theoriacodex.debug). Never touch com.theoriacodex.
