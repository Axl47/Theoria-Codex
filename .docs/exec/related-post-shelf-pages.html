Page and promote related posts

Owner: Codex · Started 2026-09-14 · Status: in progress

Purpose / context

RelatedPostsRouteController owns transient shelf requests for both Search and For You. RelatedPostsUiState is platform-free and buildRelatedFeedProjection places one full-width shelf after its canonical anchor. The route ViewModels own canonical result lists. A “page” here is one retained provider-native related response; it is presentation-only and never provider feed pagination.

Files: app-logic/.../RelatedPostsState.kt, app/.../RelatedPostsRouteController.kt, both route contracts/ViewModels, RelatedPostsShelf.kt, and focused tests.

Phases and work plan

  1. Add retained pages plus bounded current-page selection to related state; preserve stale-generation rejection and canonical-ID filtering.
  2. When a liked post belongs to the selected shelf page, remove it from retained pages, insert it after the current canonical anchor, advance the anchor, and request a new page seeded by that post.
  3. Add previous/next actions and title-adjacent arrow buttons, enabled only when their target page exists.
  4. Validate reducers/controllers/ViewModels and compile the debug source lane.

Do not persist pages, add them to normal provider continuations, recents, or viewer live paging.

Decisions

2026-09-14: Promotion is a deliberate canonical-list insertion, while all shelf pages remain transient. The shelf anchor advances to the promoted post so grid order is seed → promoted post → shelf.

2026-09-14: For You keeps an in-memory promotion overlay until a legitimate root refresh so count-only environment synchronization cannot erase an explicitly promoted card.

Surprises

The existing controller already recognized a like whose post was in loadedPosts, but only replaced the shelf; it had no canonical-list mutation hook or retained page history. Full :app:detekt remains red on 64 pre-existing long/complex-method findings; none point to the new related-state/controller/UI functions. :app-logic:detekt passed.

Outcomes / retrospective

Search and For You now share one page-aware lifecycle. Promoted cards survive ordinary FYP snapshot publication but are discarded on its next root refresh. Tests prove insertion, removal, automatic next-page selection, bounded navigation, stable anchor identity, and count-only snapshot survival.

Idempotence and recovery

All validation commands are build-only and safe to rerun. No device, database, package install, or production data is touched. If compilation encounters the known Kotlin incremental-cache registration error, let Gradle’s fallback finish or rerun the single compile lane in a fresh daemon. Revert only files named in this plan; unrelated worktree edits belong to the user.
