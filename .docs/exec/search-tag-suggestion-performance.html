Purpose / Big Picture

A suggestion lexicon is the bounded local collection of tags learned from bundled seed data, provider responses, and viewed results. Today Search waits for the provider before consulting it and examines only the first 120 stored entries. After this change, local matches publish immediately and a later healthy provider response can improve the list.

Pixiv suggestions retain the native tag as their search value and may carry a translated label. Matching considers both forms, while selection always submits the native value. Pixiv's provider order is retained when it has no comparable count.

Work Plan

  1. Add alternateText with a default to TagSuggestion.
  2. Create pure ranking in app-logic: exact, prefix, then contained; counts only inside a source/relevance band; stable provider order; round-robin Unified sources.
  3. Extend TagSuggestionStore with full-query reads and explicit origins. Persist additive fields, decode old snapshots, merge disk knowledge ahead of seeds, and replace active trending per source.
  4. Split cached-only and remote coordinator paths. Merge both, deduplicate exact prefixes for a TTL, time-limit autocomplete, and run Unified source calls concurrently.
  5. Publish cached results immediately from SearchViewModel, then remote results after debounce; preserve cancellation/generation ownership.
  6. Parse Pixiv translations, send Accept-Language, and render translated/native text without raw internal labels.
  7. Run one focused validation batch, group root-cause fixes, and update this plan and working_list.md.

Surprises And Discoveries

  • The bundled Pixiv lexicon has 477 rows, but 357 cannot participate in the current 120-before-match fallback.
  • On reload, seeds are merged before disk rows, pushing learned-only Pixiv rows behind all seeds.
  • Pixiv's null counts cause alphabetical ordering and structural demotion behind counted Unified providers.
  • One ordered list currently represents autocomplete, seeds, seen tags, count lookups, and trending.

Decision Log

  • Native identity: keep native text as the durable/search value and add one optional alternate label so translated display never changes the submitted query. 2026-09-02 / Codex.
  • Policy owner: put ranking in app-logic, matching the platform-free Search policy boundary. 2026-09-02 / Codex.
  • Storage evolution: use additive JSON fields rather than a database migration because absent optional fields remain decodeable. 2026-09-02 / Codex.

Outcomes And Retrospective

Complete. Search now publishes complete-cache matches before debounce, bounds provider autocomplete to four seconds, reuses exact source/prefix/scope refreshes for fifteen minutes, and fans Unified providers out concurrently. Ranking is relevance-first and fair across sources. Active Trending is an explicit replaceable origin. Pixiv requests the current locale, persists native/translated pairs, matches either label, displays the translation with native context, and always submits the native tag. The extraction reduced SearchCoordinator.kt to 787 lines and removed its frozen hotspot exception. The final host batch passed all relevant module tests, 555 app tests with three expected opt-in skips, Debug compilation, Detekt, aggregate Kover XML/verification, and the hotspot gate.
