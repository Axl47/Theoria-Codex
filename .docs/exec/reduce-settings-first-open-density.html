Reduce Settings first-open density

Purpose / Big Picture

On first open, Settings presents a short stack of collapsed cards instead of every control. The headers still communicate repeated-use state: active profile and likes, enabled-source count, hidden-set count, configured-account count, cached-item count, and the developer scenario. Expanding a card reveals the unchanged controls.

Context And Orientation

SettingsSectionExpansionState in app/src/main/java/com/theoriacodex/app/settings/SettingsState.kt converts persisted string keys into typed section state. SettingsViewModel restores that map through UiRestoreRepository and persists the full map after each toggle. SettingsScreen renders every card through the shared SettingsSection composable.

The compatibility boundary is a missing persistence key. Explicit true and false values remain authoritative; only absent values adopt the new collapsed default.

Phases And Work Plan

  1. Change the typed expansion state's initial and missing-key fallback values to collapsed.
  2. Add an optional one-line collapsed summary to the shared section header and supply only compact live state.
  3. Keep credentials, per-source weights, and cache-clearing controls unchanged inside expanded content.
  4. Add owner and presentation regression tests, then run one bounded app validation batch.

Surprises And Discoveries

No migration is required because existing toggles already persist a complete keyed map. New section keys naturally receive the first-open default without resetting older keys. The initial inline summary pushed the shared composable over its complexity threshold, so header text now has a focused shared owner.

Decision Log

Decision: default all sections collapsed and summarize only repeated-use state. Rationale: this provides the strongest first-open density reduction while every control remains one tap away. Date/Author: 2026-08-08 / Codex.
