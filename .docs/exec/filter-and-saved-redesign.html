Filter and Saved redesign

Purpose

Show active filters without opening a sheet, give every feed one filter sheet, apply Search's source filters together, retire minimum score, extend date filtering to every source, and give each Saved collection its own cover.

Status

Implemented and host-verified. Not exercised on a device: the date picker dialog, pill width behaviour while scrolling, and Saved covers.

Context

ui/components/FeedFilters.kt holds the button, sheet, and chips. app-logic/.../search/SearchQueryOptions.kt holds date ranges. SearchVisibilityFilters.dateRange filters on the device from the applied query, and Pixiv also receives the range server-side. codex/SavedCodexLibraryTile.kt holds the library tile.

Decisions

  • Date filtering runs locally for every source; posts without a known date are hidden. FeedPageDemand still bounds automatic paging to three pages before Continue.
  • SourceCapabilityGate no longer excludes sources for dates.
  • Query.minScore stays so stored queries decode and hash, but no source reads it.
  • Beyond two filters and while scrolling, the button shows the number at the width it already has.
  • Date ranges read in UTC, matching the picker and Pixiv's date format. Preset ranges are fixed when chosen, so an old one reads as custom dates.

Validation

With JAVA_HOME=/opt/homebrew/opt/openjdk@24/libexec/openjdk.jdk/Contents/Home, run ./gradlew test --offline, :app:compileDebugAndroidTestKotlin, and :app:lintDebug --offline --no-daemon. These are safe to rerun.
