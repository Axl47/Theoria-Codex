Purpose and context

Returning from Viewer should leave cards showing the last visible media. Search watched cards should show the same highest-seen X/Y badge and relative time as Recents. A reading position is the last visible media number; highest-seen progress remains monotonic and separate.

core-data/src/main/kotlin/com/theoriacodex/data/repository/ReadingPositionRepository.kt already persists positions independently per Recents section. app/src/main/java/com/theoriacodex/app/ui/routes/ViewerRouteWorkflow.kt records each visible media. app/src/main/java/com/theoriacodex/app/search/SearchScreen.kt renders shared SearchResultCard, reused across feeds. app/src/main/java/com/theoriacodex/app/recents/RecentsScreen.kt already supplies progress and relative time.

Phases and work plan

  1. Add observable reading positions to both repository implementations; publish only successfully persisted updates and profile replacements.
  2. Add app/src/main/java/com/theoriacodex/app/search/PostWatchPresentation.kt with shared history projection, page selection, and relative-time formatting. Subscribe once in app/src/main/java/com/theoriacodex/app/ui/TheoriaApp.kt and expose via composition local to shared cards.
  3. Select only the last page's media locations in SearchResultCard, using enriched watched metadata for lazy galleries. Preserve full post identity, actions, totals, and video index. Search supplies highest progress and watched time; Recents uses the same formatter and latest visible-media time.
  4. Add focused repository and media selection tests, update CHANGELOG.md, validate and commit.

Unwatched cards retain existing presentation. Missing positions retain original preview; out-of-range positions clamp to available media. Media loading uses existing retry/recovery UI and never falls back to another page after a saved page is selected.
