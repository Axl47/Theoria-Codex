Search composer

Purpose

Long searches were hard to navigate in a sideways chip row, "or" groups were undiscoverable, and excluded tags were removed on tap. Search now has a one-line bar over results and a full-screen editor that shows every tag. Query storage, matching, and execution do not change.

Current status

Implemented and host-verified. Not yet exercised on a device or emulator: keyboard insets in the full-screen dialog, source picker layering, and TalkBack remain open acceptance items.

Context

Paths are under app/src/main/java/com/theoriacodex/app/. The "draft" is the editable Query in SearchUiState.query.draft; results change only on SearchAction.ApplyDraft. search/SearchComposerModel.kt holds pure rules, search/SearchComposer.kt the UI, and search/CollapsingSearchChrome.kt the bar. Reducer rules preserved: alternatives must share the group's type, and Gelbooru tags must match a suggestion.

Living log

Decisions

  • Full-screen dialog, because a sheet loses too much height to the keyboard.
  • The add mode stays selected until changed.
  • Female and Male tags keep separate headings.
  • The filter button stays a floating button and the source picker stays beside the bar, rather than the mockup's in-bar gear and icon; this keeps their existing behaviour.
  • "Old Search Bar" now means the bar stays visible while scrolling.

Surprises

Terms added from a post's hold menu change the draft outside the editor, so the bar shows a Search action while changes are pending.

Outcome

Host checks pass. SearchComposerContent exceeds Detekt's length and complexity limits, as the app's other screen functions do; split it if it grows.

Recovery

Host checks are safe to rerun. If the reused daemon reports a Kotlin resolver crash in lint, rerun lint alone with --no-daemon.
