Purpose / Big Picture

A user can open any Codex collection, tap a filter FAB, and combine Animated only, animated-duration range, one represented enabled source, Language, Full Color, and Newest/Oldest/By source ordering. The top-of-grid sort row disappears. The FAB indicates non-default state, the header reports visible versus total items when filtering, and tapping a card opens Viewer with exactly the visible ordered collection.

Context And Orientation

Codex detail is the secondary screen that renders posts saved in one collection. Repository-backed sort means CodexRepository.observeCodexPosts emits the collection in the selected CodexSortMode. Route-local filters change only what the current screen displays; they do not edit the Codex or persist into its records.

Language and Full Color are local metadata filters. They are offered only when enabled NHentai or Hitomi sources are represented in the collection. Unsupported-source posts do not match an active capability filter.

Duration values can be absent in saved snapshots. The existing shared enrichment service may resolve/probe them, but only a route owner may request bounded batches and apply immutable duration-only updates. The durable Codex repository is not rewritten.

Phases

Phase 1: Pure filter contract

Add a dedicated state model and deterministic filter function. Verify source combination, animated/duration behavior, NHentai/Hitomi capability gating, taxonomy and legacy canonical-tag language matching, and full-color matching.

Phase 2: Route state and UI

Add the duration owner, place the Codex content in a Scaffold with the shared FAB, move every sort option into the sheet, and render a useful filtered-empty state. Sorting remains a callback to the repository observation.

Phase 3: Navigation and closeout

Pass the visible ordered list and selected index into Viewer, add architecture coverage, run one host-only validation batch, and update this plan and working_list.md with exact evidence.

Surprises And Discoveries

  • Codex sorting already happens in the repository observation, so moving its controls did not require a new sorting implementation.
  • Viewer launch ignored screen-level filtering because it closed over state.posts; the callback now carries the exact visible list.
  • Saved posts retain typed taxonomy when available, with canonical tags as a compatibility fallback; NHentai and Hitomi both expose Language facets.
  • The first app Detekt pass found two new composable-size issues. Extracting effect and sheet-section owners removed both. The rerun remains red only on four inherited findings in untouched CodexListScreen, SaveToCodexSheet, and SearchEmptyStatePolicy.

Decision Log

  • Decision: keep filters route-local and sorting repository-backed. Rationale: this follows the shared chrome contract without adding global persistence. Date/Author: 2026-08-10 / Codex.
  • Decision: source filtering is All or one enabled represented source. Rationale: it is the smallest predictable interpretation of “by Source” and composes cleanly with capability filters. Date/Author: 2026-08-10 / Codex.
  • Decision: enrich duration in a navigation-scoped owner without persisting resolved values. Rationale: it obeys the shared bounded enrichment contract and avoids incidental Codex mutations. Date/Author: 2026-08-10 / Codex.
