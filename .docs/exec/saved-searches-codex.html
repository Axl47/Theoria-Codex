Saved Searches as a live Codex

Open Saved Searches beside Followed in Library to browse the union of selected pinned queries. Include/exclude saved searches without deleting them; remember selections. Preserve exact grouped, source, Multi-Search and historical For You queries.

Owner: Codex · Created/updated: 2026-10-16 · Complete

Next: review the committed feature; implementation and validation are complete.

Risk: query continuation and partial failures must remain independent; virtual results must never become stored collection membership or mutate active Search/FYP state.

Context · Work · Validation · Living log · Recovery

Purpose and context

SavedSearchRepository stores device-wide named RecentSearchEntry payloads independently of Recents. FollowedCodexViewModel merges creator branches, while CodexDetailScreen provides shared media cards, filters, duration enrichment and Viewer launch. The new virtual Codex has stable ID system:saved-searches; it has no saved membership rows, deletion, export, cleaning, automatic rules or save destinations. Selection lives in FeedFabRestoreState under this Codex's existing FAB key. Empty exclusions include all saved searches; excluding every ID shows an explicit empty state. Newly saved queries start included.

Decisions

Use a virtual Library Codex plus persisted exclusion IDs, preserving pins. Keep the existing Recents picker as the individual-replay manager; the requested new Codex lives beside Followed in Library. Extract shared branch scheduling and paging/status presentation rather than duplicating Followed. Use isolated Search execution service state so this feed cannot change the active Search environment. Source-local failures stay retryable and do not halt successful queries.

Discoveries

Saved FYP payloads contain distinct native tag queries per provider. Flattening all pins into one Query would change Boolean meaning and lose source-specific semantics. SearchCoordinator already returns immutable continuations and separates execution from admitted-history persistence, making read-only virtual execution possible.

Outcomes

No provider mutations, app installation or live data changes. Final offline lint and size/whitespace gates passed. Idempotence and recovery
