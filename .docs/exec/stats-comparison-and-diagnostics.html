Purpose / Big Picture

In Settings > Your stats, Share my stats opens a preview where a person unchecks any Codex or post. The totals are recalculated and the result is sent as a JSON file. Compare with a friend opens such a file and shows both people's time and open counts, each Codex side by side, and their top posts, which open in the Viewer.

Settings > Diagnostics report shows a redacted plain-text report of crashes, Android exit reasons, recorded failures and the app's system log. The person chooses its sections and shares it as a file.

Surprises And Discoveries

  • The app had almost no logging: four main-source files use android.util.Log, and most failures are converted to UI state. A log alone would have been nearly empty, so failure points report explicitly.
  • Android's ApplicationExitInfo already records exit reasons and freeze traces, so those need no capture code.
  • The report's actions sat below a long scrolling preview, so they moved above it.
  • Automated taps on the emulator's DocumentsUI file rows did not pick the file, in grid or list view.

Decision Log

DecisionRationale
The comparison is held in memory only.Another person's numbers must never mix into local statistics. It survives a Viewer visit because it lives in SettingsViewModel.
Leaving out a post subtracts its opens and viewing time and promotes the next post.The user asked that the stats change accordingly, and nothing should reveal a removal.
Codices pair by name.Ids are private to each library and are never exported.
Logs were built in this pass.User decision on 2026-11-10: missing logs cost more later than building them now.
Redaction happens before disk and again on the report.Stored files never hold secrets, and system-log text gets the same treatment.
Share and Compare are rows under Your stats on Settings home.User asked for them at the top level on 2026-11-10; a separate hub page would only add a tap.
The post picker is a Stats-style list: the row opens the Viewer and a separate checkbox decides sharing.User needed to inspect posts before leaving them out. Reuses the Top posts row.
One commit for both features.They share the same shell and Settings wiring, so a split commit would not build.

Outcomes And Retrospective

Both features work in the running app apart from the unverified picker step. A forced crash appeared in the report with its stack after relaunch. Future failure points should call Diagnostics.report with text that names what failed and never includes browsing content.

Idempotence And Recovery

All commands can be rerun. No migration exists: the new files appear on demand, and deleting theoria_codex/diagnostics/ is safe. Use Settings > Diagnostics report > Delete saved logs to clear them. Device checks must restore any acceptance APK they replace.

Never test on com.theoriacodex. Use logs and accessibility text instead of screenshots where provider media can appear.
