A post opened from Codex will appear in the Codex Recents section even when the same canonical post already belongs to Watched, without moving or deleting either membership.

Purpose / Big Picture

Recents has separate Watched and Codex filters, but the database currently stores only one history row per post. The latest opening origin therefore chooses one section and displaces the other. After this change, section membership is an explicit identity dimension: Watched and Codex may each retain their own latest view of the same post. A user can verify this by opening a post from Search, opening that same post from Codex, and seeing it in both filters.

Context And Orientation

A canonical post is identified by provider source plus provider post ID. A Recents section is the user-facing Watched or Codex category. A Viewer origin records the route that launched Viewer and remains useful provenance, but it is not sufficient as section identity.

Work Plan

  1. Add RecentPostSection, store it on RecentPostEntry, pass it through RecentsRepository.recordWatchedPost, and key normalization by post plus section.
  2. Add optional recentsSection to ViewerLaunchContext and its Gson-backed records. Non-Recents contexts remain null; Recents launches set it explicitly.
  3. Replace origin-filtered clear operations with section-filtered clear operations. Keep exact launch origin and query hash as metadata inside each section row.
  4. Change Room entity/row/DAO/repository/importer. Bump to schema 3 using create-copy-drop-rename migration; map existing CODEX origins to CODEX and all others to WATCHED.
  5. Update the Recents destination split and All routing to use section. The combined activity feed shows the newest membership for a duplicated canonical post so All does not render duplicate post rows.
  6. Add contract, Room, migration-source, Viewer workflow/context persistence, and UI routing tests. Update AGENTS.md with the durable section-identity rule.

Surprises And Discoveries

  • The UI already records Codex opens; the initial loss occurred because both repository normalization and Room primary key deduplicated only by canonical post ID.
  • Acceptance exposed a second boundary: ViewerRoute renders from its navigation-scoped owner, while TheoriaApp recorded through a separately collected outer session snapshot. During retention handoff that outer snapshot can be null, silently defaulting the event to Search/Watched even though Viewer is rendering a Codex session.
  • The committed Recents grid/action changes touch UI files needed here, but the section fix preserves their presentation and callbacks.
  • The aggregate :core-data:detekt task reports five inherited main/test findings; the repository's baselined CI owner is :core-data:detektMain, which passed. No unrelated debt was changed.

Decision Log

  • Decision: Separate section from origin. Rationale: origin remains diagnostic provenance while section is stable user-facing membership. Date/Author: 2026-08-07 / Codex.
  • Decision: Carry section as typed Viewer context instead of parsing query-hash strings in repositories. Rationale: process restoration and reopen writes remain explicit. Date/Author: 2026-08-07 / Codex.
  • Decision: Migrate only the currently stored membership. Rationale: inventing a missing second history record would fabricate user activity. Date/Author: 2026-08-07 / Codex.
  • Decision: Visible-post persistence receives the route owner's current session in the same callback. Rationale: a separately collected outer session has a null window during retention handoff and cannot authoritatively classify the event. Date/Author: 2026-08-07 / Codex.
