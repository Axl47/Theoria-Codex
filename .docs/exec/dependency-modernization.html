Purpose / Big Picture

Keep compilation, testing, CI, and app runtime dependencies maintained without buying unnecessary migrations. New installs require Android 16 (API 36); Android 17 (API 37) remains the compilation and target platform. API is Android's numeric platform level. UI navigation, media autoplay, recovery, and persisted user data must retain their existing behavior.

Context and orientation

gradle/libs.versions.toml owns library/plugin versions. The Gradle wrapper selects the build engine. AGP (Android Gradle Plugin) builds Android packages; Kotlin includes the Compose compiler; Detekt analyzes Kotlin; Kover measures host-test coverage. Android modules are app, core-data-android, baseline-profile, and macrobenchmark. The remaining modules use JVM tests. Robolectric simulates Android for host tests. GitHub workflows separately run emulator tests and release publishing.

The WebP decoder named Legacy also implements controllable animation and static overview frames, so its dependency is not obsolete when older Android versions are dropped. Credential and database migrations remain required for existing data.

Surprises and discoveries

Old failed CI run logs return HTTP 410; job annotations only report exit code 1. AGP's minimum wrapper mismatch is independently documented, but the old emulator failures cannot be attributed from retained evidence. Current Google platform and image catalogs publish Android 17 as android-37.0, not android-37; both emulator matrices now use quoted "37.0" so the runner installs real packages. Android 16 uses "36". Gradle Actions v6 changes licensing; v6.4 also offers a basic open-source provider. User approved the enhanced provider. Android API 36 host tests require Java 21. The animation decoder cannot be removed wholesale without losing current features. Robolectric SDK 36 requires its documented Java module opens (not just JDK 21); configured once for Android host-test tasks. AGP 9.3 changed library source-set interfaces; the generated legacy DSL accessor caused a ClassCastException. Configuring the public LibraryExtension fixes it. The pre-existing hotspot gate reports TheoriaApp.kt (2004/1963), SearchScreen.kt (2057/1913), SearchViewModel.kt (1116/1100), and two stale adapter exemptions; CI acceptance now requires repairing these existing blockers. Move the app startup boundary into TheoriaAppGraph.kt, browser opening into TheoriaAppSupport.kt, source-picker UI into SearchFilterControls.kt, and initial Search state into SearchInitialState.kt. Remove the two stale adapter exemptions. Keep all line limits unchanged.
