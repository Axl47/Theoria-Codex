Purpose and context

The download queue is Activity-owned. PostDownloadQueue.kt journals native Android DownloadManager transfer IDs and an opaque marker before native enqueue. Galleries expand into separate media-page records. PostDownloadJobStore.kt persists operational identities, never provider URLs, secrets, local paths or full posts. Keep that boundary while adding bounded origin labels. Legacy records retain a generic Downloads origin. AnimationExportDestination.kt finds exported MP4s by marker rather than guessing paths.

Changes live in app/src/main/java/com/theoriacodex/app/media/: PostDownloadQueue.kt, PostDownloadJobStore.kt, PostDownloadsViewModel.kt, DownloadJobsSheet.kt, AnimationExportDestination.kt, and a local-file destination helper if needed. Discoveries

Existing durable jobs intentionally omit thumbnails and complete media payloads. Available in-process previews can be shown; restored jobs need a local-file thumbnail or a neutral fallback. Gallery pages are separate existing queue records and remain independently actionable. A pending confirmation needs parent-to-page aliases after expansion. An enqueue gap must resolve its native marker before removing the record, or an active/completed native destination can become untracked. Failed file deletion retains its original transfer status and a removal error rather than creating a network retry.

Decisions

Interpret “two posts per column” as two cards across, matching the app's browsing grids. Capture original route names at submission so later navigation does not relabel downloads. Local files take precedence over provider playback. Decisions recorded 2026-10-16 / Codex. A neutral thumbnail remains when neither a live preview nor a decodable local image is available; no provider media graph is added to the durable journal.
