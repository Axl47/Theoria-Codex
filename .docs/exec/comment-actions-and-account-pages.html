Comment actions and account pages

Status: implemented, validating · branch feat/comment-actions-profiles · follows Post comments

Goal

Comments in the Viewer's info sheet become actionable, and the people behind them reachable.

  1. Part 1, comment actions and links. Holding a comment opens a bottom sheet (the post action sheet's style): header with the author's avatar, name (a link to their profile when one can be opened) and the comment's first line; rows Copy text, Copy link, Open in browser. Tapping the avatar or name opens the profile. A copied comment link opened on the device opens the Viewer on that post with the info sheet scrolled to the comment, tinted for a moment.
  2. Part 2, account pages. A creator that is a site account (a person, not an artist tag) gets an upgraded creator page: avatar, counts (uploads, favorites, whatever the source exposes), and Uploads / Favorites tabs shown only when the source can list them. Creators that are artist tags or searches (Danbooru artists, nhentai, Hitomi) keep today's search-like page unchanged. Commenters on sources whose creator route is a tag (Danbooru, nhentai) open the new account page.

Terms

  • Comment link: the post's page URL plus a fragment naming the comment (core-domain/.../model/CommentLinks.kt). A top-level comment uses the site's own anchor when it has one (CommentsSourceAdapter.nativeCommentAnchor, e.g. Gelbooru #c123), so the link also jumps there in a browser. Replies and sites without anchors (Pixiv, nhentai) use #theoria-comment=<id> or #theoria-comment=<parentId>/<id>; browsers ignore it and Theoria reads it back (parseCommentTarget).
  • Comment author: PostComment.author, a CreatorProfile for the commenter's account, filled by each source.
  • Account creator: decided by the source in code from the profile's shape (not persisted), so saved posts and follows need no migration.

Design

  • Domain (done): PostComment.author, CommentTarget, commentLink, parseCommentTarget, CommentsSourceAdapter.nativeCommentAnchor, ExternalPostDeepLink.comment.
  • Sources: each comments adapter fills author and, where the site has one, the native anchor. Danbooru and AIBooru post links become openable.
  • App: ViewerSession carries the comment to focus; the comments controller pages until it finds it (bounded), opening a reply's parent; the sheet scrolls to the item and tints it. When it is not found the post opens normally.
  • Open profile: the existing creator page when the author is browseable there, otherwise the profile URL in the browser (Part 1); Part 2 replaces the browser fallback with the account page.
  • Part 2 contract (done): AccountProfileSourceAdapter (accountFeeds, synchronous from the profile's shape; accountDetails; accountPosts) with AccountFeed and AccountDetails in core-domain/.../model/Accounts.kt. Accounts: every Gelbooru-family creator, Pixiv and Iwara users, Danbooru creators whose uploads query is user:. Not accounts (unchanged page): Danbooru artist tags, nhentai, Hitomi. nhentai commenters keep opening in the browser (no public account data).

  • Unit tests: link round-trips, per-source author parsing from field-shape fixtures (no real comment text), fragment parsing in deep links, controller focus paging.
  • On device (com.theoriacodex.acceptance on the theoria-search-test AVD), logs and accessibility text only: hold a comment, copy its link, open it with am start -a android.intent.action.VIEW -d '<link>', read that the sheet is open on the comment.

Decisions

  • 2026-11-11: bottom sheet (option B) over an anchored menu; the name in its header opens the profile (user pick).
  • 2026-11-11: tag- or search-based creator pages stay as they are; only account creators get the new page (user).
  • 2026-11-11: sources without comment ids in URLs get Theoria's own fragment instead of a new path, so links still open the post anywhere.

Open risks

  • Pixiv account details and bookmarks follow documented app-api shapes; unverified until checked with a signed-in device.
  • Iwara avatars use the thumbnail rendition path; unverified for avatars.
  • The account page's selected tab is not kept across process death (reopens on Uploads).

Recovery

All steps are code edits on the branch; rerun any failed Gradle task. No data, schema or persisted-format changes.
