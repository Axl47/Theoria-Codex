Viewer Veil visual pass

Purpose / Big Picture

The Viewer reused the navy panels of the app's secondary screens, so it read as a screen containing an image. This pass makes it read as the image with controls on top. Capabilities and gestures do not change. When complete, opening any post shows white controls on soft shadows (the "veil"), with progress and the selected thumbnail tinted from the artwork.

Current Status

Implemented; awaiting the owner's hands-on check. Next action: the owner tries scrubbing, level gestures and bright art on the phone, using the steps under Validation.

Context And Orientation

Viewer code lives in app/src/main/java/com/theoriacodex/app/viewer/. ViewerScreen.kt draws the pager and, above it, the overlays that belong to the screen: top bar, post strip, related shelf. Each player (ViewerVideoPlayer.kt, ViewerGifPlayer.kt, ViewerAnimatedWebPPlayer.kt, PixivUgoiraPlayerUi.kt) draws its own timeline inside the page.

That split decides where shadows go. A scrim in the screen's overlay would sit on top of the timeline and dim it, so each player's timeline draws its own scrim (ViewerTimelineVeil), and the screen draws one only when no timeline is present (ViewerBottomChrome).

"Scrim" means a black gradient that fades to transparent. "Accent" means the color taken from the current artwork.

Validation And Acceptance

From the repository root, with JAVA_HOME set to JDK 21 or newer:

./gradlew --offline :app:testDebugUnitTest --tests 'com.theoriacodex.app.viewer.*' --tests 'com.theoriacodex.app.ui.*'
./gradlew --offline :app:detekt
./gradlew :app:lintDebug --offline --no-daemon

Device install uses only com.theoriacodex.debug, after checking the APK's application ID and debug signer. Manual steps for the owner: open a bright image, a video, a GIF, an animated WebP and a multi-page post; scrub near both ends; drag brightness and volume with each thumb; double-tap both sides; rotate to landscape; open and close the related shelf; swipe between posts and watch the tint change.

Surprises And Discoveries

  • A scrim cannot live in the screen overlay, because the timeline is drawn beneath that overlay inside each player.
  • Host rendering on pale gradients showed visible scrim edges that the HTML mock hid; easing stops were added.
  • Default Roboto digits are already tabular, so the jitter finding applies only to device fonts with variable digits. tnum is kept as a guard.
  • The navy status-bar band came from the root Scaffold's default background, not from the Viewer.
  • Detekt still reports MediaTimelineBar over the cognitive-complexity limit (19, reduced by this pass). Module-wide Detekt was already failing on other screens.
  • The first tint picked the most prominent hue and discarded pale colors, so skin tones won on nearly all character art and every post looked peach. It now weighs vividness above area and discounts skin.

Outcomes And Retrospective

The Viewer now has one visual system and one progress bar across media types. Host tests prove structure and behavior; they do not prove feel. The library used for device checks holds explicit media, so visual review beyond one frame was done on placeholder art rendered on the host, and final visual acceptance belongs to the owner.

Idempotence And Recovery

All Gradle commands are safe to rerun. Each phase is its own commit, so git revert removes one. There are no data migrations. Reinstalling the debug APK with adb install -r keeps its data and does not touch com.theoriacodex.
