Settings hub and Stats screen

Status: complete. Merged to local main. On 2026-11-02 the owner reported that device checks passed and the v1.0.0 release notes are up to date. Feature and worktree branches were then removed. Started: 2026-11-02.

Outcome: Settings shows its current values at a glance instead of a stack of accordions, and Stats is a separate page with time split, trends, and ranked Codices.

Purpose · Context · Work · Validation · Log · Recovery

Purpose

A user can read their setup without expanding anything, change short options from a sheet, and see how their usage changes over time. This follows the For You and Recents redesigns.

Context

  • Hub: the Settings home in app/src/main/java/com/theoriacodex/app/settings/SettingsScreen.kt. Rows use SettingsComponents.kt.
  • Pages: SettingsPage in SettingsState.kt, held by SettingsViewModel so Search's OpenSourceAccounts can open Accounts directly.
  • Stats: StatsScreen.kt, with trend bucketing in StatsTrend.kt.
  • Data: StatisticsSummary.history and CodexPostStatistic.thumbnail come from feat/stats-history-data, described in .docs/exec/statistics-history-and-thumbnails.html. History omits inactive days and keeps 400 local dates.

Expected: BUILD SUCCESSFUL. ./gradlew :app:detekt --offline reports no findings in the files this plan changed; it fails on findings elsewhere in the module.

Device checks: reported as passing by the owner on their device on 2026-11-02. No device logs or measurements are retained in this plan.

Log

  • Decision: pages live in Settings state rather than the app NavHost. They stay within the Settings tab, so bottom navigation and usage categories don't change.
  • Decision: "Other" is foreground time minus the three categories, because the tracker counts screens without a category, such as Settings, in the total.
  • Update: the persisted settingsSectionExpansion field was removed in b294d3ea. Old stored files still load; the next normal write drops the field.
  • Surprise: a post seen before the first statistics snapshot made the thumbnail owner reconcile against an empty top list and delete every retained thumbnail. Posts outside known top lists now skip disk work.
  • Surprise: the default JDK fails every Robolectric test with "Android SDK 36 requires Java 21". This is an environment issue, not a code one.

Recovery

All edits are source-only with no data migration. Reverting the UI commit restores the accordions, but expansion choices are no longer persisted after b294d3ea, so sections would start collapsed. Settings values remain in place.
