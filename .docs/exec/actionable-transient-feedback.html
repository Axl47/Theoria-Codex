Purpose / Big Picture

The shell renders one snackbar above bottom navigation. Clearing Watched, Codex-origin, Search, or All history shows target-specific copy with Undo. Hiding a recommendation seed shows Seed hidden with Undo even when the durable settings write refreshes the route. Removing one or many posts from Codex detail uses the same Undo surface. Copy, download-queued, and other passive confirmations remain lightweight; Android 13+ clipboard writes rely on the platform's single confirmation to avoid a duplicate app Toast. No persistent explanatory row or unnecessary confirmation dialog is added.

Context And Orientation

TheoriaAppContent owns the outer Scaffold and bottom navigation, so it is the only correct snackbar-host owner. RecentsScreen knows the selected history filter but must send a typed clear target rather than own feedback. RecentsRepository owns exact durable timestamps, provenance, section identity, and ordering. For You already persists normalized blacklist entries through ForYouCoordinator; it must report exactly which entries were newly inserted so a delayed Undo cannot remove pre-existing entries.

Undo is data ownership, not cosmetic feedback. Re-recording history with the current clock would change ordering and age labels, while removing an entire seed snapshot could delete entries that existed before the action. Restoration therefore preserves original rows and seed Undo carries only successful additions.

Phases

1. Exact reversible history

Add one additive repository restoration operation that merges cleared snapshots back with original timestamps, origin, section, query hash, and bounded ordering. Prove in-memory and Room behavior.

2. One shell feedback host

Add one SnackbarHost to the outer Scaffold. Convert Recents to one typed clear callback; on success show contextual Undo, and on clear failure offer Retry.

3. Reversible seed hiding

Return the exact newly inserted blacklist entries, emit Seed hidden, and dispatch a typed Undo through the existing ViewModel/coordinator refresh path.

4. Bounded closeout

Run focused contracts and one integrated host batch. Keep device acceptance explicit if no safe device lane runs.

Surprises And Discoveries

  • Recents already separates Watched and Codex by typed section, so feedback uses one clear-target enum without changing persistence identity.
  • The prior seed blacklist method returned only a count. Undo now carries the actual successful additions because normalized duplicates may already exist.
  • The durable For You settings emission can invalidate its route refresh while the seed mutation is still completing. Seed writes therefore use a mutation job outside refresh-cancellation ownership, while ViewModel lifetime still cancels them.
  • Codex bulk removal formerly looped over single deletes and discarded saved timestamps. The repository now owns atomic bulk removal and exact membership restoration, including newer re-add protection.
  • Android 13+ owns clipboard confirmation text and exposes no supported API for replacing it. The shared helper retains feature-specific success Toasts through Android 12L and omits them where the platform would duplicate feedback.
  • The generic :core-data:detekt lane is red on inherited findings in untouched migration, settings-policy, and legacy test files. The source-specific :core-data:detektMain lane passes, and no UX-002 file appears in that inherited report.

Decision Log

  • Decision: keep one host in TheoriaAppContent. Rationale: Scaffold already owns bottom navigation geometry and is the only boundary shared by the affected routes. Date/Author: 2026-08-07 / Codex.
  • Decision: make reversible removals restore exact repository snapshots. Rationale: Undo should not silently rewrite ordering, timestamps, or provenance. Date/Author: 2026-08-08 / Codex.
  • Decision: follow Android's versioned clipboard-feedback contract. Rationale: the system confirmation cannot be safely suppressed or relabeled on Android 13+, so app copy-success Toasts stop at Android 12L. Date/Author: 2026-08-08 / Codex.
