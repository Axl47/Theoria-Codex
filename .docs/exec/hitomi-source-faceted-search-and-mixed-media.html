ExecPlan: Add Hitomi Faceted Search, Creators, and Mixed Media

This plan adds Hitomi as a first-class Theoria Codex source and introduces a reusable faceted-search layer shared with NHentai. Users will be able to distinguish tags, artists, characters, series, groups, types, and languages; browse Hitomi artist uploads; open Hitomi links directly in the app; swipe through still and animated gallery pages; and play Hitomi anime MP4s inside the existing Viewer.

Purpose / Big Picture

After this plan is complete, Hitomi appears beside the app's other real sources. A user can select Hitomi, type a prefix such as kio, narrow suggestions to Artists, choose an artist without losing that taxonomy, combine the artist with character, series, type, language, and ordinary tag terms, exclude any of those terms, and apply newest, popular-month, top-year, or random ordering.

Opening a result resolves it inside Theoria Codex. A multi-page gallery keeps its page order and media count. Animated WebP pages animate rather than appearing as still thumbnails. An anime result plays its MP4 in the same Viewer used by other video sources. The media overview button remains available for any post with multiple media items, even when the current item is seekable, and the overview represents images, animated images, and videos without attempting to play every tile at once.

If gallery metadata contains artists, each artist is available as a Creator Profile action and can open a paginated Hitomi artist stream. If metadata reports no artist, the app hides the action instead of displaying N/A. Hitomi gallery, reader, anime, CG, and artist URLs route through app deep links.

Observable completion: from a release build, search Hitomi for artist:najar plus type:artistcg ordered by Popular, open gallery 4042375, use the media overview and swipe through its animated WebP pages; then open anime 7231 and play, seek, pause, background, resume, and download its MP4 without leaving the Viewer.

Context And Orientation

Current Theoria boundaries

A source adapter implements SourceAdapter and converts one provider into domain Post pages. RealAdapterRegistry constructs adapters, while app/source/SourceMetadata.kt separately decides which adapters are exposed to users. SearchCoordinator owns draft/applied query state, autocomplete, persistence, source-mode execution, Unified execution, and pagination. ViewerScreen renders a post stream, and each post can already contain an ordered media list.

The current autocomplete contract is halfway to faceted search: TagSuggestion carries a free-form type, and NHentai already supplies types such as artist, character, parody, group, language, category, and tag. However, AutocompletePanel passes only item.text into SearchCoordinator. Query persists only includeTags: List<String> and excludeTags: List<String>, so choosing an artist or character loses its meaning.

The current Viewer can render images, GIFs, Pixiv Ugoira, and videos in its nested media pager. Its media overview is intentionally image-only: viewerGalleryMediaItems removes videos, GIFs, and Ugoira, and galleryAvailable becomes false while the current item is seekable. This plan changes that global overview policy rather than adding a Hitomi-only alternate Viewer.

Canonical taxonomy

A facet is the meaning of a search term, such as Artist or Series. A source namespace is the provider's spelling for that meaning. Store both because providers do not use identical names.

Hitomi live protocol

Hitomi's search page is a client for several public data services; it is not server-rendered search HTML. The app should call those data routes directly and must not embed a WebView.

1. Autocompletetagindex.hitomi.la/{scope}/{encoded characters}.json returns up to ten arrays shaped as name, count, and namespace.
2. Candidate IDsBinary big-endian .nozomi lists return gallery IDs in source order and support byte-range retrieval.
3. Gallery metadataltn.gold-usergeneratedcontent.net/galleries/{id}.js returns a JavaScript assignment wrapping JSON.
4. Media URLsImage/AVIF/WebP hosts are derived from file hashes plus the mutable configuration in gg.js; anime MP4s use the streaming video host.
ContractVerified exampleImplementation consequence
Mixed autocompletehttps://tagindex.hitomi.la/global/t/a/g.json returns text, count, and namespaces including tag, artist, character, and series.All uses the global endpoint; an explicit scope changes only the endpoint prefix.
Scoped autocompletehttps://tagindex.hitomi.la/artist/k/i/o.json returns artist-only results.Do not fetch every scope on each keystroke. Debounce one endpoint based on the selected scope.
Gallery 4042375Type artistcg, 44 WebP file records, artist najar, series and character metadata; its first WebP contains VP8X, ANIM, and ANMF chunks.Represent 44 ordered animated-image items. Do not route them through ExoPlayer or collapse them into one video.
Anime 7231Type anime, videofilename=cheat-item-kanrikyoku-no-oshigoto-ex-1.mp4, two WebP records used as cover/poster metadata, and no artist.Expose one playable MP4 media item with a WebP poster; do not report the two poster files as a two-page post.
Video transportThe MP4 route returned HTTP 206, video/mp4, and Content-Range: bytes 0-1023/196139272.Media3 can seek and resume using byte ranges. Live health must verify range support, not download the entire file.
CDN configurationgg.js provides a changing base path plus a shard function selecting hosts such as w1/w2 and a1/a2.Parse and cache the live configuration, refresh once on media 404, then try the alternate shard before marking media unavailable.
Protocol risk: the JavaScript assets and CDN base are implementation details maintained by Hitomi and can change without notice. Keep captured fixtures for deterministic tests, but treat the opt-in live health report as the current truth. A parse failure must degrade only Hitomi and include the failing URL/config version.

Work Plan

Implement in phase order. Do not expose Hitomi in SourceMetadata.exposedRealSources() until the adapter, sparse-card stability, resolution, headers, and deterministic source tests pass. Keep each phase independently reviewable and use a user-facing Conventional Commit message after each completed phase.

  1. Add byte-range HTTP support and Hitomi protocol fixtures/tests. Ensure text adapters see no behavioral change.
  2. Add typed search/post domain models and persistence migration. Run core-domain and core-data tests before changing Search UI.
  3. Build scoped search UX and prove it first with NHentai. This isolates product/model correctness from Hitomi network complexity.
  4. Implement Hitomi protocol helpers, adapter, pagination, URL resolution, registry wiring, stub fixtures, and exhaustive enum updates. Keep exposure disabled until this step is green.
  5. Add typed post actions, multiple artists, Creator Profile support, and gallery/artist deep links.
  6. Generalize the Viewer overview and add animated WebP/API-level support plus anime video mapping.
  7. Expose Hitomi, run live/app/device checks, update current-facing docs and this plan, and close only with recorded evidence.

Surprises And Discoveries

  • The captured artist list anchors the acceptance gallery: the 116-byte artist/najar-all.nozomi fixture decodes to 29 big-endian IDs and begins with 4042375. The live endpoint returned HTTP 206 with Content-Range: bytes 0-115/116, proving the same byte path used by deterministic tests.
  • Animated example is not a video: gallery 4042375 contains 44 WebP file entries, and the sampled file contains WebP animation chunks. This requires an animated-image path, not Media3 video.
  • Anime posters are not pages: gallery 7231 has two WebP records plus one top-level videofilename. Hitomi's own gallery logic uses these as cover/poster material and renders one video.
  • Search is binary: search result HTML is only a shell. Typed searches read big-endian Nozomi ID lists, so the current text-only HTTP abstraction is insufficient.
  • CDN paths move: the live gg.js base and shard routing are required to construct working image URLs. A hard-coded URL worked on one shard and returned 404 on the other.
  • Existing UX already carries type halfway: NHentai suggestions retain taxonomy in TagSuggestion.type, but selection discards it. The shared model is therefore a correction of an existing information-loss boundary, not only new Hitomi UI.
  • Provider identity is wider than text: NHentai can return the same value as both a general tag and an artist, and gendered tag namespaces can also share text. Suggestion caching and selection therefore require source + facet + namespace + normalized value identity.
  • Recommendation vocabulary remains source-sensitive: typed taxonomy decides which terms are general tags, but Pixiv must still prefer its native rawTags ordering over translated canonical aliases. The shared recommendation/cache projection intersects those two rules instead of replacing either one.
  • Sparse cards are a protocol boundary: resolving only one WebP poster per Search result avoids constructing every page's mutable CDN candidates during bounded hydration. Ordered AVIF-first page candidates are deferred until the post opens.
  • Nozomi membership must stay compact: include intersections and exclusions use sorted primitive IntArray caches rather than boxed ID sets, keeping large provider lists bounded in memory.
  • Random pagination needs a snapshot, not only a seed: one bounded full-index read is fingerprinted before shuffling, and the digest travels in the page token. A cached order resumes exactly; after eviction the adapter refetches and rejects changed provider bytes rather than applying an old offset to a new permutation.
  • Media refresh crosses source and Viewer layers: a generic recovery capability lets Hitomi reconstruct file/config identity from persisted URLs, refresh gg.js once for the failed version, and replace only matching media. Search and Viewer trigger it only for exact HTTP 404s, preserve cancellation, and retain normal candidate fallback.
  • Creator links require one identity boundary: provider artist metadata, persisted/imported profiles, app-link slugs, and creator pagination must agree on canonical case, whitespace, separators, Unicode validity, and a 256-code-point limit. A shared contract prevents generated links or stale profiles from becoming dead actions.
  • Post-action state is an acknowledged mutation: a typed action can be rejected when its source is unavailable. The chip now changes only after the coordinator confirms the exact term is current, so saved/imported posts cannot display a search state that was never created.
  • Animated WebP needs two decode modes: normal Viewer requests animate, while Media Overview requests deliberately decode a distinct cached first-frame bitmap. Hitomi overview tiles select WebP instead of AVIF so the same cross-version path works on API 26 and newer without autoplay.
  • Legacy animation safety includes decoded size: compressed-byte limits alone do not bound a lazy decoder. The API 26/27 path validates the VP8X canvas against a 32 MiB ARGB frame cap, reads and initializes on an interruptible IO dispatcher, and rejects malformed or oversized canvases before the drawable reaches Compose.
  • Adjacent video prefetch must not become a download: a 16 MiB ranged probe can cache only a response proven complete and small. Partial or large responses remain remote so Media3 performs normal ranged streaming and seeking instead of duplicating the full MP4 in background work.
  • gg.js can invert shard polarity without changing its API: the live configuration changed from default shard 1 / listed cases shard 2 to default shard 2 / listed cases shard 1. Modeling the explicit case keys together with their selected shard supports both shapes; assuming every listed key means shard 2 would silently generate a wrong primary URL.
  • Live checks must preserve cancellation as control flow: the preexisting health runner caught every Throwable, which turned cancellation into a false provider failure and let abandoned work cross the reporting boundary. Both generic and Hitomi-specific checks now rethrow cancellation before classifying transport failures.
  • Source filters are part of test truth: targeted app smoke must intersect the real exposed-source set with the requested sources and reject unknown names. Otherwise a Hitomi-specific test can run during an unrelated provider check or a typo can silently skip the intended route.
  • Desktop JVM regex acceptance does not prove Android startup safety: Android ICU rejected the escaped object-brace expression used by the startup-loaded Hitomi gallery parser even though its JVM tests passed. A deterministic assignment scanner now avoids engine-specific syntax, and a connected-device test initializes and exercises the real protocol object.
  • Android transparent gzip breaks partial binary streams: the Galaxy reproduced valid gamecg and multi-tag Nozomi failures inside Android's gzip inflater. A range may end before the compressed stream does, causing premature EOF or a decoded body whose length no longer matches Content-Range. The shared byte-range transport now requires Accept-Encoding: identity, keeping header and body offsets byte-exact on every runtime.
  • Connected tests do not replace the production package: this project gives debug builds the com.theoriacodex.debug suffix. Instrumentation exercises that package alongside the non-debuggable production com.theoriacodex; installed-build claims must name which package was launched or inspected.
  • Sparse Search cards are also the fastest Viewer bridge: waiting to resolve all 44 pages before creating the Viewer made gallery 4042375 feel stalled and left its Search animation frozen during the transition. Hitomi Search now opens immediately on its animated WebP preview, while the Viewer's existing background resolution replaces that lightweight post with the complete gallery.
  • Facet vocabulary needs a zero-input path: autocomplete alone cannot teach users a closed vocabulary before they know what to type. The shared faceted-source contract now supports source-owned featured values; Hitomi exposes Type and Language choices when those scopes are selected, while All remains a visually unprefixed plain-term surface.

Idempotence And Recovery

All planned migrations are additive and should be safe to rerun. No destructive database reset, cache wipe, or history deletion is required.

  • Interrupted persistence migration: keep record fields optional and read legacy fields first when typed fields are absent. Never rewrite user files merely by reading them. Normal repository writes can upgrade a record later.
  • Bad page token: treat opaque token parse/hash/version failure as a fresh first page or a typed source error; never use an offset from a different query.
  • Partial Nozomi response: reject byte counts not divisible by four, retry according to normal HTTP policy, and preserve the previous Search page if pagination fails.
  • CDN 404: invalidate the cached gg.js config once, refetch, rebuild candidates, try the alternate shard once, then mark that media unavailable. Do not loop.
  • Gallery hydration failure: skip or mark only the failed gallery card. Preserve source order and do not fail a whole page because one gallery was removed or blocked.
  • Media failure: provider TLS/socket/stream failures during background prefetch become unavailable media; coroutine cancellation is rethrown. The current Viewer session remains alive.
  • Animated decoder experiment: keep API 26/27 support behind focused code and tests. If a trial dependency fails quality or size requirements, remove it cleanly and record the alternative; do not leave two active decoders.
  • Resume after interruption: read Current Status, Progress, the latest Decision/Discovery entries, and working_list.md. Run the last phase's focused command before continuing.
  • Rollback: before source exposure, removing the Hitomi registry/exposure entry isolates unfinished protocol work. After typed persistence ships, retain readers for typed fields even if Hitomi exposure is temporarily disabled.
