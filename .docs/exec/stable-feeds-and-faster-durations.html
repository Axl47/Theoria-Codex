Stable feeds and faster durations

Purpose / Big Picture

With a duration filter on, posts appeared only after scrolling stopped, and earlier posts could land above the viewport and reshuffle the grid. On every feed, closing the Viewer and scrolling back up moved cards between columns. After this work, filtered posts keep arriving during a scroll, shown cards keep their position, and feeds keep their columns across the Viewer.

Current Status

Implemented and proven on a physical Samsung S24+ for Gelbooru. Pixiv and Hitomi were not exercised end to end on the device; see Validation. Next action: the developer's manual check on the phone.

Context And Orientation

A "lookup" finds a post's duration. MediaDurationCoordinator schedules lookups, MediaDurationAcquisitionEngine chooses how to answer one, and BoundedMediaDurationProbe reads ranges of the media file. A duration filter hides a post until its duration is decided.

The "frontier" is how far through a feed posts have been revealed. LazyVerticalStaggeredGrid is the Compose grid. It remembers each card's column by list position, in memory only, and rebuilds columns by guessing when that memory is missing. scrollToItem lines every column up at one card, which later forces a full reassignment.

Surprises And Discoveries

  • Search re-applied its saved position with scrollToItem on every route resume. Retaining grid state alone left 12 to 14 cards jumping at each deep return; the layout log showed column offsets becoming equal.
  • Gelbooru's img4 host answers an overloaded client with 404 for files it can serve. The same URL returned 404 from the Mac straight after a phone burst, then 206 shortly after. The pre-change build lost posts to this too.
  • Parallelism alone made throttling much worse: about 10 requests a second produced mostly 404s.
  • Most lookups in the tested Gelbooru query are GIFs, which cannot be measured without downloading them, so a duration filter hides them.

Decision Log

  • Late posts join the bottom. The developer chose this over skipping them: the filter serves discovery, so smoothness matters more than exact order, and appending never disturbs the grid's position-based memory. 2026-11-03, developer and Claude.
  • Pass a stuck post after eight later decisions, not after a timer. A count adapts to network speed: on a slow network everything is slow together. 2026-11-03, Claude.
  • Keep the Compose grid. A custom layout would remove the guessing, but five screens depend on the current grid and the measured jumps are gone without it. 2026-11-03, Claude.
  • Gelbooru starts one lookup per 500 ms. It resolved faster overall than 300 ms, which spent more time in cooldown. 2026-11-03, Claude.
  • Gelbooru durations stay on the probe path. The API rejected a keyless request, and no Gelbooru response was inspected. The adapter already reads a duration field when one is present. Hitomi's gallery data has no duration field. 2026-11-03, Claude.

Outcomes And Retrospective

Lookups were never individually slow; the rules around them caused the wait. Two jumps and a missing history caused the reshuffling, so the fix is mostly removing behaviour. A single-line log of column offsets found the second jump faster than reading code had. Restoring after process death still jumps, because no column history survives it. It is rarer, and no moves appeared in the one post-restart scroll measured.

Idempotence And Recovery

No destructive operations or schema changes are involved. Every build and test command can be rerun. Each phase is a separate commit that can be reverted alone. A throwaway baseline can be built with git worktree add at 3b48c6e2; remove it with git worktree remove. Never install to com.theoriacodex.
