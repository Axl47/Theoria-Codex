Curated Tagged Releases

Theoria Codex now publishes one immutable, user-explained prerelease per intentional version tag. Normal work can reach main without rewriting a release.

Status: Implemented and validating · Created/updated: 2026-07-10 · Owner: Codex

Purpose / Big Picture

A version bump becomes a clear release boundary: its commit contains the app version and plain-language notes, and its annotated tag tells GitHub Actions to build and publish that exact snapshot. Users see a curated changelog, while developers can push ordinary changes without creating an update.

Context And Orientation

PathRole

release-notes/vX.Y.Z.mdTracked, user-facing GitHub release body and in-app changelog.

Version-code contract. The app and updater both use 1_500_000_000 + major * 10_000 + minor * 100 + patch. Keeping the code high is necessary because installed releases already compare against that range.

Phases

1. Make release intent explicit

Completed: workflow trigger changed from pushes to main to pushes of a SemVer tag. It rejects mismatched tag, name, code, or notes before signing.

2. Supply curated text

Completed: each release includes a matching Markdown body committed beside the version bump. The previous commit-to-changelog generator is no longer part of the workflow.

3. Add the release skill

Pending user approval: the skill will draft and validate the release commit, present notes for review, and create/push the annotated tag only after approval. No skill implementation is included in this change.

Surprises And Discoveries

The source file had a low local code (43), but release builds override it to the SemVer-derived code. Respecting that old value would make Android reject updates as downgrades.

Decision Log

Decision: retain the SemVer-derived high code rather than migrate numbering. Rationale: it keeps every installed updater and Android package manager on one monotonically increasing sequence. Date/Author: 2026-07-10 / Codex.

Outcomes And Retrospective

The workflow now has one immutable release boundary and uses curated notes. The future skill remains intentionally deferred for review.

Idempotence And Recovery

Local test commands are safe to rerun. A failed tag-triggered workflow does not alter the tagged source commit; fix the release commit, create a new version/tag, and push that new immutable tag. Do not move an already published tag. GitHub release publishing is the only external mutation and occurs only after all workflow preflight checks pass.
