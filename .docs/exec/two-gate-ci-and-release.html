Purpose / Big Picture

A small fix used to pass five gates in sequence: a PR gate, a main gate, the same two again for a version-bump PR, then a tag gate. That was about 50 minutes of CI and several approvals. After this plan there are two gates. To see it working, approve release notes and watch one Release run create the tag and publish.

Verified code means the exact file contents, identified by Git's tree hash, passed scripts/check.sh. The result is stored under refs/verified/<tree>, so identical code is never checked twice.

GoalThe same command verifies code on the Mac and on GitHub.

Phase 3: One release run

GoalApproving notes leads to a published prerelease with no other human step.

Surprises And Discoveries

  • Observation: Two of the four most-failing tests had already been fixed. Evidence: collectionActionsRename… last failed Nov 4 and coldGraphRelaunch… last failed Nov 2.
  • Observation: The offline and grouped-search journeys fail as a pair because of a system dialog. Evidence: the failure screenshot shows "System UI isn't responding" over a correctly rendered image, the sampled pixel matches the dialog in all three inspected runs, and logcat shows the dialog taking input focus. The dialog cannot be cancelled, so the grouped test's real Back press never reaches the app.
  • Observation: The emulator lane also catches real problems. Evidence: a stale Saved heading, a new JSON field, and R8 acceptance read failures on Nov 8 and Nov 10.
  • Observation: main has no branch protection. Evidence: GET branches/main/protection returns 404, and three PRs were merged with red checks.
  • Observation: Offline lint fails on a runner with a cold Gradle home, because the lint tool itself is not cached. Evidence: No cached version of com.android.tools.lint:lint-gradle:32.3.3 available for offline mode. A dry run now fetches it first. The Mac's warm cache had hidden this.

Decision Log

  • Decision: Run emulator tests only in Release, weekly, or on request. Rationale: they are the slowest and most failure-prone lane, and releases are frequent enough to find a break quickly. Date/Author: 2026-11-10 / user.
  • Decision: Create the tag last, from the workflow. Rationale: a failed release no longer uses up its version number. Date/Author: 2026-11-10 / Claude.
  • Decision: Commit release files straight to main. Rationale: a PR would add a gate for files that cannot change behavior, and the gate script proves that is all the commit touched. Date/Author: 2026-11-10 / Claude.
  • Decision: Key results by tree hash in a Git ref, not a commit status. Rationale: squash and merge commits change the SHA but not the tree, and git ls-remote needs no checkout. Date/Author: 2026-11-10 / Claude.
  • Decision: Handle emulator infrastructure failures with gh run rerun --failed, not automatic retries. Rationale: passing jobs are kept, it needs no code, and retrying assertions could hide races. Date/Author: 2026-11-10 / Claude.
  • Decision: Baseline profiles refresh only when startup or journeys changed. Rationale: the step needs a free emulator and would otherwise block a fully automated release. Date/Author: 2026-11-10 / Claude.

Idempotence And Recovery

scripts/check.sh is safe to rerun. Records are force-pushed, so re-recording a tree is harmless. A failed Release creates no tag and can be dispatched again. To roll back, revert this plan's commits, which restores the old workflows. Stale refs/verified/* entries are small and can be left in place.
