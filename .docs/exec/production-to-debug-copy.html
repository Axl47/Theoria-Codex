Purpose · Context · Phases · Validation · Living log · Recovery

Purpose

A connected-device Python command copies production profiles, libraries, Likes, saved searches, follows, preferences, Recents, reading positions, and source credentials into isolated Debug storage. Production export never writes its live logical stores or refreshes provider tokens. Public APKs contain no exporter code or component.

Context and orientation

app/build.gradle.kts defines isolated Debug and public release variants. ProfileBackupService and ProfileBackupCodec in core-data implement bounded, sanitized logical metadata backups and journaled additive restore. RoomProfileBackupStore owns the library mapping. Credentials use a package-bound Keystore envelope. Ordinary application startup performs durable recovery, so a separate :developerCopy process must skip that graph.

The personal release is opt-in through a pinned Debug SHA-256 signing-certificate fingerprint, uses the production application ID, and must be signed with the existing production key through the signed release path. It is not a connected Gradle install lane.

Surprises and discoveries

Normal startup migrates credentials/settings and recovers destructive/native intents; it cannot be used as the production export path. Existing restore deliberately preserves the selected profile and allocates fresh identities, requiring an explicit imported-profile selection option and deterministic operation ID for this command. Android's older BEGIN IMMEDIATE APIs fail on read-only WAL databases; use the unchanged PRAGMA data_version guard instead, including between cursor windows. Exclude framework-owned android_metadata from temporary schema replay. The Baseline Profile plugin automatically creates debug-signed personal derivatives; disable both before variant creation and block all personal package-mutating tasks. Fresh Debug must finish its own library migration proof before admitting restored rows; normal startup and the importer now share core-data-android/src/main/kotlin/com/theoriacodex/data/android/room/ProfileLibraryReadiness.kt. AtomicFile.openRead is not a read-only operation when .bak/.new artifacts exist; the export credential store disables recovery, rejects unfinished files, and avoids directory creation. A default untyped :core-data:detekt run reported existing unrelated issues; the repository's actual typed :core-data:detektMain passes without suppressions.

Decisions

2026-10-13 / Codex: use a separate optional personalRelease variant, not a switch on public release. Use direct Binder-authenticated content-provider pipes; no credential files on the computer, shell output, or portable backup. Export uses strict read-only source decoding and temporary logical SQLite staging, not copies of live database/DataStore files. Restore is additive to preserve existing Debug work; changed snapshots may add a new restored set.

Idempotence and recovery

Never clear, uninstall, downgrade, or automatically install production. The script may stop and launch only Debug after verifying both installed identities. Temporary production cache staging contains metadata only and is deleted after snapshot construction. An interrupted restore resumes its existing journal; a completed identical snapshot uses the same identities. Credentials are written only after complete payload validation and profile restore. Retry the same command after resolving an error; do not print secret-bearing exceptions. Public releases can replace the personal release normally when version/signature rules allow, removing the bridge.
