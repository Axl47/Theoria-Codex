Purpose / big picture

All nine findings from the read-only audit are in scope. Unified searches must start independent providers immediately and retain successful providers when another times out. Typing must not scan the tag lexicon on Main (the Android UI thread). Same-query refresh must keep its cards visible. Viewer must reuse prefetched GIF bytes, show matching previews, and resolve the next sparse post before a swipe. Completed results must not wait for best-effort caching or statistics.

Context and orientation

A root search starts a new result generation; a continuation contains provider tokens for subsequent pages. Unified combines independent providers using deterministic weighted interleaving. Query-owned ordering and post identity must remain stable: this plan uses bounded provider deadlines, not arrival-order feed insertion. Autocomplete may publish multiple updates inside its existing stale-generation guard.

Work plan

  1. Implement source execution policy and extract compatibility mapping from SearchCoordinator to keep hotspot budgets stable.
  2. Implement background autocomplete, immutable normalized lookup snapshots where beneficial, and streamed provider improvements using the existing generation boundary.
  3. Separate admitted UI results from ordered durable writes; batch the two applied-query keys. Keep failure feedback and final-write ownership explicit.
  4. Retain same-query grid composition and show lightweight refresh progress. Different-query loading keeps the existing clear transition.
  5. Introduce a shared GIF acquisition seam used by prefetch and Movie decoding, with a matching preview beneath loading content.
  6. Add bounded Viewer resolution lookahead and remove durable thumbnail caching from the resolver's return path.
  7. Add focused behavior tests for new concurrency, timeouts, persistence, loading and media boundaries. Run the final validation batch and update this document and AGENTS.md with important contracts.

Surprises and discoveries

Full-suite verification exposed a pre-existing stale FeedFabRestoreState wire manifest: searchAnimationByScope and its nested restore type were missing. The manifest and nested R8 keep rule now match the existing schema. Async tests now inject the same test scheduler used by their route owner; local suggestions remain before debounce, but no longer execute on the input callback stack. Viewer resolution must invalidate old prefetch keys before warming full media. Prepared continuations must retain client-side exclusions.

Search state already retains old content during a root request; the screen alone hides it. Query persistence writes one JSON file twice. GIF Movie transport bypasses Coil's disk cache.

Lint initially lacked lint-gradle:32.1.1 in the offline dependency cache. After dependency resolution it crashed inside Kotlin FIR/UAST while analyzing ViewerScreen.kt; the final isolated offline retry with --no-daemon passed after code generation completed. No lint suppression or relaxed configuration-cache policy was added. Final command: LINT_PRINT_STACKTRACE=true ./gradlew :app:lintDebug --offline --no-daemon --console=plain; BUILD SUCCESSFUL. The final Viewer and real Search refresh test rerun, Debug assembly and app Detekt passed after the GIF-ready placeholder handoff was tightened.
