Purpose / Big Picture

Theoria already has deterministic provider tests and an opt-in health command, but current live health is too shallow for source drift. It mostly asks, "Can this adapter run a newest search?" It does not prove a seeded tag search works, whether autocomplete/trending tags are still shaped correctly, whether returned media URLs avoid 403/404 with the headers the app actually uses, or whether the app search workflow still routes real sources correctly.

After this plan is implemented, a developer can run one live command before a release and get a structured report that says which source broke, which route broke, what query or media URL was involved, whether the failure was 403/404/rate limit/auth/parse drift, and whether the failure happened in the source adapter or the app-level Search route.

Boundary: this is not a replacement for deterministic tests. Fixture tests stay in the default test lane. Live tests are a release-health and drift-detection lane.

Context And Orientation

A source adapter is a SourceAdapter implementation such as GelbooruSourceAdapter, NhentaiSourceAdapter, or IwaraSourceAdapter. It knows how to search one provider and return domain Post objects. A registry is RealAdapterRegistry, which exposes source adapters to app workflows. A seeded search is a known, source-specific query that should be stable enough to prove basic source behavior, for example a common tag search plus an autocomplete prefix.

The app-facing path is not just an adapter call. In normal usage TheoriaAppGraph creates RealAdapterRegistry, then SearchCoordinator applies the selected mode, settings, enabled sources, tag autocomplete policy, search history, and result storage. Good live coverage should exercise this path too.

Phases

Phase 1: Define Probe Cases And Result Model

Create a reusable source probe model that can describe per-source seeded searches, autocomplete prefixes, expected tag echo policy, media reachability policy, and credential requirements.

GoalA future source check reports exact step outcomes instead of one generic provider status.
Specific editsAdd ProviderProbeCase, ProviderProbeStepResult, and ProviderProbeReport under core-sources/src/main/kotlin/com/theoriacodex/sources/health/. Add default cases under core-sources/src/main/resources/provider-probes/source-probe-cases.json or a Kotlin object if resources are not already wired. Keep source cases overrideable via a Gradle property such as -Ptheoria.providerProbeCases=/absolute/path.json.
Seed shapeEach case should define source, mode, includeTags, autocompletePrefix, strictTagEcho, requiresCredentials, and mediaProbe. Use stable, broad tags from existing source tests and tag_store.json; avoid brittle trend-only tags.
Commands./gradlew :core-sources:test
AcceptanceDeterministic unit tests prove case parsing, missing/invalid case handling, and result status mapping without network access.

Phase 2: Expand Opt-In Source-Level Live Health

Replace the single newest-search check with a multi-step source probe that can identify where a source broke.

Goal:core-sources:providerHealthCheck -Ptheoria.liveProviders=true reports seeded search, autocomplete, trending, resolve, and adapter media metadata health per source.
Specific editsExtend ProviderHealthChecker or introduce ProviderProbeRunner. For each exposed case, run quickQuery(NEWEST), search(seedQuery), autocompleteTags(prefix), trendingTags(limit), resolvePost(firstResult.id), and metadata checks on returned Post media fields. Map SourceAdapterException, HTTP 403, HTTP 404, empty body, parse exceptions, and credential absence to typed messages. Update core-sources/build.gradle.kts so providerHealthCheck forwards theoria.liveSources.strict and theoria.providerProbeCases as JVM system properties.
Strict modeDefault live command writes a report and exits 0 for inspection. Add -Ptheoria.liveSources.strict=true to fail the Gradle task when required cases are FAILED or when strict tag echo fails.
Commands./gradlew :core-sources:test, ./gradlew :core-sources:providerHealthCheck, ./gradlew :core-sources:providerHealthCheck -Ptheoria.liveProviders=true
AcceptanceThe skipped/offline command remains deterministic. The live report includes one row per source step with source, check name, query/tags, status, latency, item count, sample post id, and failure detail.

Phase 3: Add App-Level Live SearchCoordinator Route Smoke

Exercise the same app workflow users hit when they search, not just direct adapter calls.

GoalAn opt-in app JVM test proves SearchCoordinator routes source-mode and unified searches through RealAdapterRegistry, applies seeded tags, records statuses, and surfaces failures without crashing.
Specific editsAdd app/src/test/java/com/theoriacodex/app/search/LiveSearchCoordinatorRouteTest.kt. Gate it with Assume.assumeTrue(System.getProperty("theoria.liveSources") == "true"). Build RealAdapterRegistry with DefaultSourceHttpClient(connectTimeoutMs = 8000, readTimeoutMs = 12000, maxRetries = 0), an environment-backed credentials provider, and exposedRealSources(rule34XxxConfigured = credentialsPresent). Instantiate SearchCoordinator with in-memory repositories and a temp-backed FileBackedTagSuggestionStore. Update app/build.gradle.kts unit-test options so Gradle project properties such as -Ptheoria.liveSources=true, -Ptheoria.liveSources.sources=..., and -Ptheoria.providerProbeCases=... are forwarded to the JVM test process as system properties.
App route checksFor each app-exposed source case, call setMode(QueryMode.Source(source)), prepareTagSearch(includeTags, mode), applyDraft(), refreshAutocompleteSuggestions(prefix), and loadTrendingTags(forceRefresh = true). Assert non-crashing status, no raw 403/404 hidden as unknown, non-empty results for required sources, and tag suggestions shaped according to the source's normalization policy.
Commands./gradlew :app:testDebugUnitTest, then ./gradlew :app:testDebugUnitTest -Ptheoria.liveSources=true --tests '*LiveSearchCoordinatorRouteTest*'
AcceptanceDefault app unit tests skip live work. With live enabled, source-mode checks use actual app coordinator state and report source-specific route failures. Unified mode can be limited to a small configured subset to avoid slow fanout.

Phase 4: Probe Media URL Reachability With App Headers

Prove that returned media URLs are usable by the same header policy Search, Viewer, and downloads use.

GoalDetect media URLs that search successfully but fail when the app tries to load or download them.
Specific editsAdd an app-side live media probe helper under app/src/test/java/com/theoriacodex/app/media/ or include it in the live route test. Use postDownloadMediaCandidate(post) to select media and SourceKey.requestHeaders() with DefaultSourceHttpClient.get(). Include Range: bytes=0-0 where safe to avoid large downloads.
Commands./gradlew :app:testDebugUnitTest -Ptheoria.liveSources=true --tests '*Live*'
AcceptanceFor each source with a media candidate, the probe reports HTTP 2xx/3xx as OK, HTTP 403/404 as failed, and unsupported/credential-gated media as skipped with a clear reason. The failure message includes the sanitized URL host/path and source, not just "Unknown error".

Surprises And Discoveries

  • Observation: existing live health uses QuickQueryKind.NEWEST only. Evidence: ProviderHealthChecker.check() builds adapter.quickQuery(QuickQueryKind.NEWEST) and checks only returned item count.
  • Observation: app exposure differs from adapter availability. Evidence: RealAdapterRegistry supports AIBooru, but SourceMetadata.exposedRealSources() does not expose AIBooru and gates Rule34XXX behind configuration.
  • Observation: app media reachability needs app-module header policy. Evidence: SourceMetadata.requestHeaders() lives in the app module, while source adapters live in core-sources.
  • Observation: there is already broad deterministic tag/contract coverage through core-stubs/src/test/kotlin/com/theoriacodex/stubs/StubProviderContractTest.kt and source adapter fixture tests. The missing coverage is live drift and app-route integration, not basic domain contracts.

Decision Log

  • Decision: keep all live work opt-in. Rationale: live providers can rate limit, block, change domains, or require credentials, so normal CI must remain deterministic. Date/Author: 2026-07-04 / Codex.
  • Decision: add app-level route smoke in app/src/test rather than only expanding core-sources. Rationale: the user specifically wants real app routing paths, and SearchCoordinator is where tags, settings, history, statuses, and source-mode routing meet. Date/Author: 2026-07-04 / Codex.
  • Decision: use strict mode as a separate flag. Rationale: source drift should be visible in reports by default, while release verification can opt into failing the command when required checks break. Date/Author: 2026-07-04 / Codex.

Outcomes And Retrospective

Planning only. Implementation has not started. The plan identifies four useful additions: richer live source probes, app-level SearchCoordinator live routing, media URL reachability with app headers, and release-friendly reporting.

Idempotence And Recovery

All default commands should be safe to rerun and should not perform live network work. Live commands may create or overwrite JSON reports under build/reports/; those files are generated artifacts and can be deleted safely.

If a live check fails, do not immediately weaken the test. First inspect the report row: source, step, query, HTTP status, failure reason, and sample URL. A 403/404 is useful evidence of source drift. A credential-missing result should stay SKIPPED unless the command was run in a strict credential-required mode.

If live probes become too slow, reduce default live case breadth or add a per-source include list such as -Ptheoria.liveSources.sources=GELBOORU,NHENTAI. Do not move network checks into default ./gradlew test.
