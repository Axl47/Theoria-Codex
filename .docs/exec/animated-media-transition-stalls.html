Purpose / big picture

The user reports temporary slowdown mainly for videos/GIFs on Samsung with Gelbooru and Pixiv. Keep transitions responsive while provider data arrives and video decoders change. A lease is temporary exclusive ownership of one reusable player; returning it detaches controls/surfaces and stops playback without synchronously releasing the player thread.

Surprises and discoveries

HTTP byte transport runs off Main, but provider HTML/JSON parsing resumes in the route's dispatcher. Viewer disposal calls ExoPlayer.release() synchronously. Feed already reuses players, but its idle-release timer does not account for active Viewer playback.

The first host batch found the restoration fixture racing a real Default worker against an auto-advanced 15-second timeout. The workflow now accepts a provider dispatcher, and virtual-time restoration tests pass their scheduler. The first screen follow-up collided with another Gradle run deleting the same binary results file; rerunning with a distinct binary-results directory passed. Concurrent edits to ViewerRoute, ViewerViewModel and their tests belong to another work stream and were preserved.

Decisions

2026-10-14 / Codex: reuse the existing slot policy instead of creating a new lifetime state machine. Keep external controls exclusive to each mounted Viewer binding; retain independent players for overlapping bindings. Use background acquisition boundaries rather than moving route state ownership to a worker thread.
