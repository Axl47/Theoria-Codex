Purpose · Context · Work plan · Validation · Living log · Recovery

Purpose

Open Codex → Followed to browse posts from existing local follows. Its floating filter button selects multiple Authors and Sources: OR within each set, AND across sets, empty selections mean all. Authors use provider identity, never display names. Creator management remains available.

Context and orientation

core-data/src/main/kotlin/com/theoriacodex/data/repository/CreatorFollowsRepository.kt owns local memberships. app/src/main/java/com/theoriacodex/app/creator/CreatorFollowsViewModel.kt owns follow/unfollow and manual checks. The new collection is a virtual collection (a navigation entry backed by follows, without saved-post memberships) and must not enter save/export/statistics projections.

app/src/main/java/com/theoriacodex/app/codex/CodexDetailScreen.kt provides the existing shared cards, duration enrichment, actions and Viewer launch. app/src/main/java/com/theoriacodex/app/ui/routes/DestinationStateBoundaries.kt loads route data; app/src/main/java/com/theoriacodex/app/ui/TheoriaApp.kt wires navigation. FeedFabRestoreState in core-data/src/main/kotlin/com/theoriacodex/data/repository/Repositories.kt stores independent filters through UiRestoreRepository.

Acceptance states: no follows explains how to follow; loading is visible; unmatched filters offer Reset; failed creators are named with Retry while successful posts remain; paging uses raw provider continuation even for empty or duplicate pages; replacing filters or follows cancels obsolete requests.

Surprises and discoveries

The initial build failed on a corrupt Kotlin incremental cache (EOFException); a host-only retry with -Pkotlin.incremental=false -Pkotlin.compiler.execution.strategy=in-process passed. Static analysis prompted moving Followed-specific presentation into separate components instead of adding complexity to the shared screen. Unrelated related-post changes appeared during work and are left untouched. Their in-progress test signature and SearchViewModel size blocked shared-workspace aggregate validation, so task-owned changes were copied onto HEAD in /tmp/theoria-followed-validation. Validation there excludes the concurrent work. Current follows retain post IDs only, so a post feed requires provider acquisition. Display names are not creator identity. Existing follow membership IDs protect unfollow/re-follow races.

Decision log

2026-09-14 / Codex: user confirmed posts, not creator cards. Preserve existing local follows and use a virtual collection; source/author filters choose provider branches before fetching. Keep two concurrent requests and 15-second creator deadlines.
