Post comments

Status: in progress · branch feat/post-comments

Goal

Show read-only provider comments for a post in the Viewer's info sheet, and show how many comments a post has on search cards (where the listing says) and in the Viewer (every supported source), so people don't open each post to check.

Terms

  • Family: an API dialect shared by several sites. Theoria has two booru families, DANBOORU and GELBOORU_02 (core-domain/.../source/CustomSites.kt). Built-in Gelbooru, rule34.xxx, Danbooru and Aibooru use the same adapter classes as custom sites of those families, so a family implementation reaches all of them.
  • Comment hint (CommentHint): what a search listing already says about comments. Exact count, "none", or "some".

Design

  • Domain (done, 2f77fcdf): CommentsSourceAdapter.comments(post, pageToken, parent), CommentPage, PostComment, Post.commentHint in core-domain. The hint is never persisted.
  • Sources (core-sources): each family/adapter implements the interface and fills commentHint from listings. Gelbooru family tries DAPI XML first and falls back to the post page when the answer is not comment XML.
  • App: a session-cached CommentsLoader (like RelatedPostsLoader) fetches the current Viewer post's first page unless its hint says none. The Viewer top bar shows a comment button with the count when there are comments; it opens the info sheet. Search cards show a comment mark from the hint. The info sheet (option A) collapses tags to a one-row peek when comments exist, starts expanded when none, and is always collapsible; comments follow the tags with author avatar, name, relative date, text, stamps, and expandable replies.
  • Avatars are shown (user decision, 2026-11-11); remove them if they cause moderation problems.

Decisions and surprises

  • Gelbooru's comment API is disabled by the site; the post page is the source of truth there.
  • Viewer Info lives in an overflow menu, so the Viewer indicator is its own top-bar button rather than a badge on Info.
