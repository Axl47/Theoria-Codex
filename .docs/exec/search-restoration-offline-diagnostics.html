Search restoration and offline image diagnostics

Owner: Codex. Created/updated: 2026-10-17. Status: implementation and host validation complete. Next: API35 acceptance and offline failure diagnosis under issue #24.

Restore the intended canonical Search position after navigation or restart, without consuming it before its page arrives or overwriting it from initial layout. Preserve actionable image evidence if the offline journey fails.

Context · Work plan · Validation · Living log · Recovery

Purpose and context

A canonical index is the post's index before local filtering or transient related shelves. SearchScrollEffects.kt projects that index onto the rendered grid. It currently falls back and acknowledges even if only the first page exists. SearchViewModel.persistScroll also accepts layout events while a request is pending. Two temporary host reproductions proved both behaviors; October 3 CI logs do not prove which caused the original timeout. October 14 API35 XML shows both reported journeys passing.

Phases and work plan

  1. Implement readiness: wait while the target is beyond loaded canonical results and continuation remains; retain on errors; fall back only after exhaustion. Reevaluate only pending requests as content settles. Preserve one-shot acknowledgement after application.
  2. Request missing pages through FeedPageDemand's existing three-page budget and Continue action. Do not create a second paging owner or history/statistics events.
  3. Block both UI observation and ViewModel persistence until acknowledgement. A real DragInteraction.Start supersedes the pending restore; programmatic scroll does not.
  4. Add focused delayed-page Compose and owner/policy tests, including exhaustion, failure, user drag and page append stability.
  5. Keep the offline cyan assertion unchanged. On timeout save screenshot, root/window/display geometry and insets, sampled RGBA/color space, decoded retained-file pixels and request lifecycle. Collect files even when instrumentation fails.
  6. Run bounded host/build/static validation, inspect any safe device lane availability, commit the scoped change. Close #24 only if its complete acceptance is evidenced.
