Search query editor ExecPlan

Status: implemented and verified on an emulator; physical-phone and TalkBack checks remain open. Follows: search-composer.html.

Purpose

A search is "all of these groups, none of those tags", and a required tag is simply a group of one. The editor hid that structure behind type headings, a three-way add mode, a target row repeating tags already on screen, and actions at the bottom of the screen. It now shows the query as one readable expression and edits tags where they sit. Query storage, matching, and execution do not change.

Context

Paths are under app/src/main/java/com/theoriacodex/app/search/. The "draft" is the editable Query; results change only on SearchAction.ApplyDraft. SearchComposerModel.kt holds pure rules, SearchComposerQuery.kt renders the query and each tag's menu, and SearchComposer.kt owns screen layout and add-target state. Preserved reducer rules: a group's alternatives share its type, and Gelbooru tags must match a suggestion.

Validation

Host: ./gradlew :app-logic:test :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin :app:detektDebug :app-logic:detektMain, then ./gradlew :app:lintDebug --offline --no-daemon and python3 scripts/check_hotspots.py. Robolectric needs Java 21 or newer.

Device: on an isolated package, run DEVICE_TEST_CLASS=com.theoriacodex.app.journeys.SearchNavigationJourneyTest scripts/verify_debug_device.sh app. Connected tests uninstall com.theoriacodex.debug when they finish, so on a phone whose Debug install holds data, use an emulator.

Living log

Decisions

  • Type headings go away: with draft order and a small type prefix, the logic stays together. Long artist and character searches are where this could prove wrong.
  • Excluding stays selected until changed, matching the earlier decision about the add mode, but now sits beside the field.
  • Undo restores a snapshot, so it is withdrawn as soon as another edit or a source change lands, rather than overwrite that edit or put tags into a source that cannot search them.
  • Favorites, Undo last search, and Reset move to overflow. Favorites may deserve a visible spot later.
  • The scope row shows only once there is text, because it only matters for what is being typed.

Surprises

The tag menu's popup takes window focus and hides the keyboard while open; the keyboard returns after "Add an alternative". Connected tests would have uninstalled a Debug install holding data on the attached phone, so proof ran on an emulator.

Outcome

Host checks, lint, and Detekt pass. On an API 36 emulator, SearchNavigationJourneyTest passes, and a temporary real-touch, real-keyboard journey covered the menu, in-place alternatives, excluding, removal undo, a long query, overflow, and search. The real Debug APK was driven through the menu and in-place alternatives. Not yet exercised: a physical phone, TalkBack, and long real artist or character searches.

Recovery

Host checks are safe to rerun. If the reused daemon reports a Kotlin resolver crash in lint, rerun lint alone with --no-daemon.
