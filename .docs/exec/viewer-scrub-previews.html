Purpose / Big Picture

Dragging the Viewer timeline displays a thumbnail and target timestamp without seeking playback. Release commits once; cancellation commits nothing. The fullscreen passive bar remains non-interactive.

Current Status

Complete, Codex, 2026-10-16. Implemented and host-validated; ready to commit. Hardware/provider thumbnail acceptance remains a manual check.

Context And Orientation

All renderer paths live under app/src/main/java/com/theoriacodex/app/viewer/. MediaTimelineBar.kt currently invokes onSeekChanged on every drag. ViewerVideoPlayer.kt seeks ExoPlayer, while ViewerGifPlayer.kt and PixivUgoiraPlayerUi.kt move AnimationPlaybackState. A scrub is a temporary drag target independent from playback. VideoPlaybackInfrastructure.kt provides request-specific headers and shared cache binding.

Phases

1. Replace continuous seeks with a preview slot and release/cancel callbacks. 2. Render GIF/Ugoira previews from loaded frames; extract video thumbnails independently. 3. Verify actual pointer gestures, compile, analysis, and line budgets; commit.

Work Plan

Edit MediaTimelineBar.kt, ViewerVideoPlayer.kt, ViewerGifPlayer.kt, and PixivUgoiraPlayerUi.kt. Add ViewerScrubPreview.kt for the thumbnail UI and video extraction. Add media3-inspector-frame in gradle/libs.versions.toml and app/build.gradle.kts. Preview errors display locally and never fail playback. Add app/src/test/java/com/theoriacodex/app/viewer/MediaTimelineBarTest.kt. Keep frame updates renderer-local; no persistence changes.

Validation And Acceptance

From the repo root run ./gradlew :app:testDebugUnitTest --tests com.theoriacodex.app.viewer.MediaTimelineBarTest :app:compileDebugKotlin :app:detektDebug --offline --continue, python3 scripts/check_hotspots.py --base HEAD, and git diff --check. First dependency resolution may need online Gradle. Tests must show preview targets change during a held drag with zero seeks; release seeks once to the final target; cancellation/removal seek zero times. Physical acceptance: drag video/GIF/Ugoira while playing and paused, verify a thumbnail above the thumb and seek on release only. Host tests cannot prove hardware frame decoding or authenticated provider playback.

Living Log

Progress: repository and Media3 1.10.1 APIs inspected; shared release/cancel gesture, renderer previews, and three host gesture tests implemented. Compile and all three tests passed. Discovery: Media3 1.10 moved FrameExtractor to media3-inspector-frame and accepts the existing MediaSource.Factory. Decision, Codex, 2026-10-16: use loaded animation frames and a low-resolution video extractor, never the live playback player, for previews. Outcomes: dragging changes the thumbnail target without seeking playback; release commits once; cancellation/removal commits none. The preview uses a non-focusable popup anchored above the track, clamped to window edges, because the real playback footer Surface clips its children. Host gestures render inside ViewerPlaybackFooter to exercise that boundary. GIF preview reuses the canvas renderer; Ugoira uses its decoded timeline and explicitly shows buffering for unavailable frames. Video uses closest-keyframe thumbnails at 144 by 84 pixels, one conflated request and a six-second deadline. Removed obsolete continuous-seek throttling. Scrub transitions no longer replay a previous double-tap command.

Idempotence And Recovery

Compile, tests, and diff checks can be rerun. Dispose cancels outstanding preview work and closes the extractor. Retry by starting a new drag; playback remains usable on preview failure. Revert only this feature commit to undo. Preserve the unrelated .docs/exec/production-to-debug-copy.html edit. No production or daily-driver channel actions.
