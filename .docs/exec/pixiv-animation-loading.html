Purpose

Ugoira is Pixiv's animation format: a ZIP of image frames plus timing metadata. Previously the app waited for metadata, a full ZIP download, two full archive validation passes, and all frame decoding. Thumbnail loading remains independent; motion should begin when the first decoded batch is ready. Every visible animation remains eligible to play simultaneously.

Phases and work plan

  1. Separate transport and decoding from loading. Remove repeated decode-time full archive validation; retain complete validation once per archive acquisition and bounded frame reads.
  2. Share progressive snapshots between same-post/size consumers. Reference-count both playback and archive jobs; remove abandoned jobs before cancellation so returning cards can retry immediately. Use existing cancellable HTTP connection helper, bounded acquisition concurrency, three attempts, and a 30-second operation deadline.
  3. Persist frame timing next to the validated ZIP, bound cache entries and bytes, remove sidecars when pruning, and reuse valid disk pairs without an API request. Size card decoded playback to 16 MiB and Viewer to 64 MiB using power-of-two sampling; preserve export resolution and the existing hard memory cap.
  4. Publish the first small frame batch during decoding and further batches without restarting the timeline. Keep available frames visible while buffering, preserve pause/seek/completion semantics, and cancel on route/lifecycle exit. No partial playback enters the completed cache.

Discoveries

The injected SourceHttpClient is only used for auth in the existing animation client. Metadata and ZIP downloads use independent HttpURLConnection operations. Archive acquisition outlives its cancelled playback consumer; incomplete results must retain shared-consumer isolation.

Host bitmap stubs can accept invalid image bytes; the existing shared-failure test now injects its intended decode failure explicitly. Buffering must clamp the clock itself because a late frame tick can otherwise signal completion before recomposition notices unavailable frames.

Decisions

September 15: Keep the full ZIP download and existing archive safety checks; stream decoded frame batches afterward. Network ZIP streaming would substantially expand format/recovery complexity. Persist metadata using explicit JSON fields, not new reflected wire models. Retain full-quality exports. User waived device benchmarks; focused correctness checks only.

Outcomes

Implemented all five reviewed improvement areas. Fresh loads still download the complete ZIP and perform one full safety validation, then publish four decoded frames followed by batches of eight. The clock holds at the available boundary. Same-key consumers share publication; different sizes share archive acquisition; cancellation of the last consumer disconnects transport. Valid disk ZIP/timing pairs bypass credentials and metadata calls on reopening. Completed card and Viewer playback fits bounded per-item and global caches; exports bypass decoded-cache retention. No measured speedup claimed.

Recovery and idempotence

Host commands are safe to rerun. Never clear user app data or install an APK. Unrelated Codex/creator edits already exist in the workspace and are outside this task. Invalid or missing cache sidecars fall back to metadata acquisition; incomplete downloads use temporary files and are deleted on cancellation. Roll back only this plan's files/hunks if needed.
