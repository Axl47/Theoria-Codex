Purpose

Make fullscreen browsing direct and fluid, keep recommendation seeds reachable, and simplify Search and the Codex library. A Codex is a local collection; Saved includes Likes, Followed authors, and Saved Searches. Each requested change is a separate commit.

Context and design

The Android app uses Kotlin and Compose. ViewerScreen owns nested horizontal post and gallery pagers; ViewerMediaPage hosts renderers and gestures. ViewerRoute binds the navigation-scoped reducer to shared likes, preferences, and provider data. SearchVisibilityFilters in app-logic applies visibility rules. core-sources owns provider HTTP adapters. Settings persist through repository settings and profile backup.

Use the existing MaterialTheme palette (surface, onSurface, primary, outline, error), current typeface and typography scale. Use titleLarge for Saved and labelLarge for child names/counts. Reserve boldness for the full-width Saved card. Viewer thumbnail cells are compact squares with a primary selection border; motion answers drag, selection, expansion, or dismissal. No new visual language or assets are required.

Data flow: persisted preferences → route render configuration → controls/renderers; feed likes → recommendation controller → retained seed visibility and viewer shelf. UI states include collapsed/expanded chrome, first/last post edges, unresolved gallery pages, loading/empty/failed related results, cancellation, and session replacement. Keep current post stable during navigation motion and commit selection at settling. Provider errors remain retryable and distinct from empty results.

No device installations or production access. All visible animated feed cards must keep simultaneous autoplay. Host tests cannot establish live authentication, hardware behavior, TalkBack, or thermal performance.
