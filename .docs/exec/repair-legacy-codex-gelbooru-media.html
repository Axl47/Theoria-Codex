Purpose / Big Picture

The Codex is a durable library, so saved posts must survive provider URL drift. After this repair, old Gelbooru records use a compatible canonical media host, gray cards can re-resolve themselves by post ID, successful refreshes update the saved record for future launches, and failed prefetches never crash the process.

Context And Orientation

codex_store.json stores full Post snapshots. CodexDetailScreen renders those snapshots through SearchResultCard. TheoriaApp.prepareViewerPostsForLaunch can resolve one selected post, while ViewerScreen prefetches the current and adjacent videos.

Work Plan

  1. Add a narrowly scoped Gelbooru URL canonicalizer for numbered video-cdn subdomains and cover it with adapter tests.
  2. Apply that policy to current adapter output and legacy media candidates without weakening TLS verification.
  3. Add updatePost to the Codex repository contract; replace only known saved snapshots and persist every actual replacement.
  4. Let Codex cards request resolution after preview failure and have the app update the repository when resolution succeeds.
  5. Broaden Codex/Recents refresh eligibility to include preview-only legacy records.
  6. Contain prefetch connection/stream exceptions while preserving coroutine cancellation and cleaning partial files.

Surprises And Discoveries

  • The visible gray-card bug and fatal Viewer bug share stale provider URLs but are separate failure boundaries: cards never re-resolve Gelbooru, while Viewer prefetch does re-use the stale URL and throws.
  • A successful Viewer refresh originally healed the post record but not every thumbnail representation. A stale local thumbnail file outranked the refreshed URL pointer until the cache entry was replaced as one unit.
  • The Viewer route collapsed provider exceptions and a true missing-post result into the same nullable outcome, preventing deleted posts from receiving honest terminal copy.

Decision Log

  • 2026-07-10 / Codex: Keep certificate verification intact. Rewrite only the known Gelbooru-owned numbered video CDN hosts to the certificate-valid canonical host.
  • 2026-07-10 / Codex: Heal saved data through a repository update contract instead of making the Viewer the long-term owner of refreshed posts.
  • 2026-07-11 / Codex: Refresh the durable post and its cache entry together, deleting all older representations of the same thumbnail key before writing the replacement.
  • 2026-07-11 / Codex: Treat an adapter returning no post as terminal deletion, while preserving thrown provider/transport failures as recoverable.

Outcomes And Retrospective

The saved-media lifecycle now heals the saved post, the keyed thumbnail cache entry, and the visible Codex cover model together. Known broken Gelbooru CDN hosts are repaired at both current-source parsing and legacy app media boundaries. Network prefetch failures no longer escape the Compose coroutine. A provider-confirmed missing post now reaches the Viewer as the terminal message Post was deleted, distinct from retryable provider failures.

Idempotence And Recovery

All planned tests and builds are safe to rerun. Repository replacement is idempotent for equal posts and must never alter Codex membership or saved timestamps. No destructive migration is planned: legacy JSON remains readable, and URL repair occurs at the media boundary plus on normal successful refresh.
