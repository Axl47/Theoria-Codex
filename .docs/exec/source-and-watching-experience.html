Purpose · Context · Phases · Validation · Living log · Recovery

Purpose

Users can recover one failed source without losing other results, select video quality, revisit followed creators, choose what happens at playback completion, use a floating video and headset controls, and browse comfortably in wide windows.

Context and orientation

SourceAdapter is a provider integration. SearchContinuation holds provider page tokens and prepared queries; retry must preserve both. ImageRef represents one gallery item, not alternate quality versions. ViewerSession is the ordered post stream opened from a feed. Renderer timing stays outside route state. Settings uses typed DataStore; durable Gson records require wire-contract updates.

Phases and work plan

  1. Source actions: details sheet, account setup navigation, open provider, retry only failed source. Append canonical unique results without moving accepted rows; retain exact failed-page token. Verify isolation, pagination, cancellation and no new Recents event. Commit feat(sources).
  2. Quality: preserve typed alternate video renditions, add persisted playback/download choices and metered/roaming policy, apply selection centrally. Explicit resolutions in Viewer. Preserve selected position across rendition changes. Test selection and storage round trips. Commit feat(media).
  3. Local creator follows: durable source/creator identity, Follow toggle and saved list, manual refresh with new-since-visit indicators. No remote follows or background polling. Test identity and persisted boundaries. Commit feat(creators).
  4. Playback: Loop, Play once, Next in queue. Default loop retained. Advance media then post in the current stream; stop safely at its end. Match renderer completion and lifecycle behavior. Commit feat(viewer).
  5. Platform playback: Viewer-only MediaSession for headset controls and explicit picture-in-picture, single player retained while floating; no session for feed previews. Hide Viewer chrome in PiP, preserve pause/resume and release on exit. Commit feat(playback).
  6. Adaptive: preserve Material theme; navigation rail at wide widths, adaptive overview columns and useful width constraints. No new tab. Preserve current route and scroll during resize. Commit feat(layout).

Design: retain existing semantic Material colors, typography and secondary app bars; media is the visual focus. Compact windows keep bottom tabs; wide windows move destinations to a left rail and leave content flexible. New controls use concise sentence-case labels and existing sheets.

Validation and acceptance

Run from repository root. Per feature run focused owner tests with ./gradlew :app:testDebugUnitTest --tests '*FeatureTest*' and applicable module tests. After implementation run ./gradlew :app:testDebugUnitTest :app-logic:test :core-domain:test :core-data:test :core-data-android:testDebugUnitTest :core-sources:test :app:compileDebugAndroidTestKotlin, then Detekt and ./gradlew :app:lintDebug --offline. Retry isolated lint with --no-daemon for the documented FIR resolver crash only.

Acceptance: retry a failing source while another remains visible; change quality without restarting position; reopen a followed creator after process recreation; play once stops, next advances, loop repeats; headset pause controls Viewer, PiP continues and restores fullscreen; resizing preserves selected tab and scroll. Device checks require packaged non-production identity and signing preflight before install. Build-only checks are not device or performance evidence.

Surprises and discoveries

Source chips currently have no click action. Failed Unified page tokens are discarded; source retry must retain their input. Video variants are discarded by adapters. Viewer video player is owned by composition.

Decisions

2026-09-12 / Codex: six feature commits, each updating this plan. Creator follows are local with manual refresh. Queue means current Viewer stream. No added top-level destinations. Preserve concurrent visible autoplay.
