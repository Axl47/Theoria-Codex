Purpose / Big Picture

A user can tap a small overflow icon beside a collection title and item count to export, share, search, rename, or delete it. Inside a collection, tapping Edit enters selection mode; card taps select posts and one Remove action removes the selected set. Long-press remains available for the full single-post action sheet. Search, Recents, For You, Creator, and ordinary Codex post cards gain no permanent overflow button.

Context And Orientation

A “Codex” is the app's saved collection. CodexListScreen.kt renders collection tiles and already owns the complete collection action sheet, but that sheet is reachable only by long-press. CodexDetailScreen.kt renders shared SearchResultCard cards and currently exposes removal only inside the long-press PostActionSheet. TheoriaApp.kt connects both screens to existing transfer and repository operations.

The tile overflow must be a nested click target so it opens actions without opening the collection. In detail, normal card taps open Viewer only outside edit mode; edit-mode taps only change selection. Long-press continues to open the existing single-post action sheet outside edit mode.

Phases

1. Explicit collection actions

Add a compact overflow icon beside the existing title and item count. It targets the same actionTarget state as long-press, so export/share/search/rename/delete retain one owner and one set of dialogs.

2. Explicit post selection

Add immutable edit-selection state. Edit is disabled for an empty Codex. While active, cards show a compact selected/unselected marker; card taps toggle membership; Cancel exits without mutation; Remove exits mode and submits the selected posts through one callback.

3. Bounded verification

Test state transitions, compile Android UI wiring, run the app unit suite and Detekt once, validate this plan, and record exact evidence. Device interaction is not required for host implementation and will not be inferred if it is not run.

Work Plan

  1. Extend CodexGridTile with an onOpenActions callback and a labeled overflow icon in the metadata row.
  2. Add CodexEditSelection as the single state transition owner, including reconciliation when observed posts change.
  3. Update CodexDetailScreen to switch header and card behavior by selection mode while leaving the long-press action sheet intact.
  4. Change detail removal wiring to accept a list and remove each selected membership through CodexRepository.removeItem.
  5. Add focused tests, run one validation batch, then update the checklist and this plan with outcomes.

Surprises And Discoveries

  • The collection-level action sheet already contains every requested action, including source/tag-scoped Search; discoverability needed a second entry point, not a second action implementation.
  • The shared feed card has no modifier hook for selection decoration. The detail screen preserves that shared owner by wrapping cards and rendering a route-local selection marker rather than changing all five feeds.
  • The first Detekt pass identified that the new branches pushed existing composables over complexity and length limits. Extracting the metadata row, detail header/actions, selectable grid, and card reduced ownership size without suppressing the rules.

Decision Log

  • Decision: treat UX-001 as the complete first backlog item. Rationale: its acceptance bullets define one cohesive discoverability change across collection list and detail. Date/Author: 2026-08-07 / Codex.
  • Decision: keep bulk removal as repeated existing membership removals rather than add a repository transaction. Rationale: the backlog asks for UI selection and does not require new persistence semantics; each existing operation is already idempotent. Date/Author: 2026-08-07 / Codex.
  • Decision: keep delete confirmation but do not confirm ordinary selected-post removal. Rationale: deleting a collection is explicitly irreversible, while removing selected memberships is an ordinary, recoverable collection edit. Date/Author: 2026-08-07 / Codex.

Outcomes And Retrospective

UX-001 is implemented and manually accepted by the user. Every Codex tile exposes its existing collection actions through a labeled overflow icon while long-press remains available. Codex detail has an explicit Edit mode with selected/unselected markers, Cancel, and count-aware removal; normal card taps and long-press retain Viewer and full-action behavior outside edit mode. The immutable selection owner drops posts removed by observed repository updates. Focused selection tests passed 3/3; the full app lane passed 409 tests with zero failures/errors and three unchanged opt-in skips; Android-test Kotlin compilation and Detekt passed, with Detekt retaining its known 10 analyzer-resolution diagnostics. HTML and diff checks passed. No agent-run device, emulator, connected test, package mutation, live provider, release, tag, or push command ran.

Idempotence And Recovery

All planned Gradle, HTML, and diff checks are safe to rerun. The implementation adds no schema, file format, migration, or destructive script. If interrupted, inspect this plan, working_list.md, and git diff; selection is ephemeral Compose state and repository removals remain idempotent for already-removed memberships.
