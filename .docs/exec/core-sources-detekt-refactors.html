Purpose / Big picture

Provider adapters translate remote responses into canonical posts, the shared identities and media used by Search and Viewer. Smaller responsibility boundaries make search continuation and media behavior easier to maintain. Existing fixture tests must keep producing the same posts, requests, continuation tokens, diagnostic statuses, and typed failures.

Context and orientation

The Kotlin/JVM module core-sources owns provider adapters. Detekt is its static code analysis tool. Keep Detekt's own parallel setting disabled and leave its rules and baseline unchanged. No production, live-provider, build-channel, or UI changes are required.

Work plan

  1. Split ProviderProbeRunner.runCase into its existing diagnostic steps and pure seeded-post predicates. Preserve sample capture before result evaluation and preserve step ordering and failure isolation.
  2. Move Hitomi query compilation, version binding and compiled-index models into HitomiQueryCompiler. Share the existing global-index cache with HitomiNozomiReader.
  3. Move binary-index transport and membership/size caches into HitomiNozomiReader. Preserve scan budgets, consumed raw IDs, request bounds and range validation before hydrating posts.
  4. Move Hitomi post mapping and media recovery together into HitomiPostMapper. Reuse ParsedHitomiGallery.hasPlayableVideo for sparse video and poster decisions.
  5. Separate Pixiv media, page and tag parsing; preserve canonical media preference, progressive URLs and native/translated tag order.
  6. Move nhentai pure gallery mapping and suggestions out of the adapter, retaining legacy/new image formats, sparse mirror behavior, page ordering, declared counts, cleaned title selection and artist authorship.
  7. In core-sources/src/test/kotlin/com/theoriacodex/sources/nhentai/NhentaiResolutionSourceAdapterTest.kt and core-sources/src/test/kotlin/com/theoriacodex/sources/pixiv/PixivSourceAdapterTest.kt, move long response setup into named fixtures. Retain every behavioral assertion.

No new runtime feature, UI state, rule suppression, dependency or baseline change is part of this work.
