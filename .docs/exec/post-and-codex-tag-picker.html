ExecPlan: Post and Codex Tag Picker

Status: implemented; validation evidence below. Companion: the Search editor redesign, search-query-editor.html, on its own branch.

Purpose

Post info and a Codex's "Search with these tags" each offered a list of tags and fed a search, but neither showed that search, and each drew tags differently. Both now use one interaction: a list of tags to pick from, and a tray showing the query being built. Query storage, matching, and execution do not change.

Context

The "draft" is Search's editable Query; results change only when it is applied. A "typed" tag has a type such as artist, and belongs to one source. "Portable" general tags have no namespace and can follow the draft between sources.

Phases and work plan

  1. Reducer: post tags can join groups; report what a source switch would drop; tag searches carry typed groups and exclusions.
  2. Shared chip and tray, then post info and the Viewer's compact row.
  3. One Codex sheet replaces the source sheet and the slider sheet; Auto-save's picker uses the shared chip.

Validation and acceptance

Host, with Java 21 or newer: ./gradlew :app-logic:test :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin :app:detektDebug :app-logic:detektMain, then ./gradlew :app:lintDebug --offline --no-daemon and python3 scripts/check_hotspots.py.

Device: a temporary real-touch journey on the isolated API 36 emulator, using fixture data with a plain color as media. It ran both surfaces and asserted the queries sent to the source.

Surprises and discoveries

  • Observation: addPostTerm silently removed typed terms when a typed tag came from another source. Evidence: its filter on isPortableGeneralTag. It now asks first.
  • Observation: addIncludeAlternative would reject post tags on Gelbooru, because it validates typed input against suggestions. Post tags take their own path.
  • Observation: Draw left the filter's keyboard open, hiding most of the list. Evidence: emulator screenshot. Draw now clears focus.

Decision log

  • Decision: Tag list first, with Draw as a secondary control. Rationale: the mock's layout; the owner was asked which they use more and did not answer, so this is easy to revisit. Date/Author: 2026-11-04 / Claude.
  • Decision: Keep type headings here though the Search editor drops them. Rationale: a query has logic to show, while a post's tags are a description whose natural structure is type. Date/Author: 2026-11-04 / Claude.
  • Decision: Chips always reserve the count slot. Rationale: late counts must not reflow chips; sources without counts show slightly wider chips. Date/Author: 2026-11-04 / Claude.
  • Decision: The tray's terms are read-only; editing them stays in the Search editor. Date/Author: 2026-11-04 / Claude.

Outcomes and retrospective

Both surfaces shipped as designed. Not established: live provider behavior, TalkBack with a real screen reader (semantics are tested), and feel of the tap cycle, which only the owner can judge.

Idempotence and recovery

No migrations or destructive operations. Device runs reinstall only the isolated debug package and can be repeated.
