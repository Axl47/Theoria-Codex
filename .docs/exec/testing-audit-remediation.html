Purpose and acceptance

The user asked to handle every finding in the testing audit. Tests should fail when the corresponding behavior breaks: clearing before Undo, exact provider requests/order, canonical identities, complete persisted upgrades, profile isolation, route replay/restoration, OCR analysis, transport limits, and actual visible media playback. Numeric performance comparisons must reject incompatible measurements and detect calibrated regressions. Preserve useful unit tests and narrow build/architecture guards; replace source-spelling checks that claim runtime behavior.

No production install, live provider account mutation, translation-service deployment, or production data cleanup is authorized. Isolated Debug, acceptance, and benchmark lanes are in scope after packaged identity and signing verification.

Context and orientation

app owns Android screens, navigation and platform integration. app-logic contains platform-free behavior. core-domain owns query meaning and orchestration, core-sources implements real providers, and core-data-android owns Room (the on-device SQL database). macrobenchmark measures physical-device startup and interaction. The translation gateway is Python in the legacy-named deploy/libretranslate/ directory. A fixture is controlled representative external input; it must not replace the production behavior under test.

The initial audit inventoried 1,262 methods across 235 files. The host batch succeeded with 1,168 runtime cases, including three intentional live-source skips; 40 Python tests passed. Existing coverage dated September 4 was 58.2%. These are baseline context, not post-change validation.
