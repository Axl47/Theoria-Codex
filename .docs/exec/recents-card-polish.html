Recents and card polish ExecPlan

Status: implemented and verified on the emulator; physical-phone feel, scroll performance and TalkBack remain open. Branch: feat/recents-card-polish, cut from the v1.3.0 release state and rebased onto main later.

Purpose

Recents still showed searches in the styling from before the search composer redesign, and the overlays on every post card had five unrelated shapes (round like button, gray count pill, square black labels, separate source badge, eye badge) that crowd the 164dp shelf tiles. We compared options in a T3 Code mockup, and the user chose:

  • Cards: "edge scrim". No pills. Soft gradients along the top and bottom edges carry plain white icons and text: like (top-left), media count (top-right), ▶ duration (bottom-left), and time, watched eye and source logo (bottom-right). When we know which page of a gallery was reached, a thin primary-colored progress line runs along the bottom edge. Fallback if the emulator shows a noticeable performance cost: the "glass capsule" design, without blur.
  • "All" view: searches grouped per day. Each day reads: heading, one horizontally scrolling row of compact search tiles, then that day's posts in one carousel. The order in which searches and views interleaved within a day is no longer shown, by choice.
  • Searches tab: a middle ground between the quiet list and the query chips. It's a container-less list with dividers. The query is styled text over up to two lines (muted "or", red "−" exclusions), with a source tile on the left, a meta line (For You, kind, sources) with the time on the right, and the visible Save button kept.

Data, storage, tap and long-press targets, accessibility labels, and simultaneous autoplay don't change.

Context

Paths are under app/src/main/java/com/theoriacodex/app/. search/SearchResultCard.kt is the one post card used by Search, Recents, Codex and For You; its overlays were drawn by SearchCardBadges. Recents is recents/RecentsScreen.kt; the All view's rows come from recentsTimeline in recents/RecentsTimeline.kt. ReadingPosition stores only a gallery media number, not a video position, so videos cannot get a progress line.

Living log

Decisions

  • The progress line appears only where a gallery's viewed media number is already known (the Watched section and watched search results). Videos keep the eye mark, because no playback position is stored.
  • Scrims have fixed heights (56dp top, 72dp bottom) rather than fractions of the card, so tall portrait cards don't get half-dark.
  • Follow-up from review: all corner marks share one inset (10dp sides, 8dp top and bottom) and an 18dp row height, so the eye, source logo and duration sit on one line. The heart's press ripple is a circle centered on the heart instead of the square 48dp target. Card and Viewer like buttons share ui/motion/LikeFeedback.kt (haptic, pop, LikedHeartColor).
  • Search tiles in the All view save on long-press only. The Searches tab keeps its visible Save button, which existing tests and discoverability depend on.

Surprises

Edge scrim needs no blur, so the "blur is too slow, fall back to glass" condition never came up: the card draws two gradient rectangles instead of four or five small pills. Emulator frame timing isn't acceptance evidence for this repo, so no performance comparison was recorded.

Outcome

Host: :app:testDebugUnitTest, :app:compileDebugAndroidTestKotlin, :app:detektDebug, offline lint and the hotspot gate pass. On the theoria-search-test AVD (Debug package, APKs checked with verify_device_apk.py, ro.kernel.qemu=1), SearchNavigationJourneyTest, SavedSearchJourneyTest, ForYouPostActionsJourneyTest and CompactControlAccessibilityDeviceTest pass (11 tests). A temporary, uncommitted instrumentation test seeded Recents with the journey fixture's solid-cyan images (no provider media) and paused on the All, Watched and Searches views for screenshots. Those confirmed the per-day search tiles, the single per-day shelf, readable white marks over a bright image, the 4/12 gallery progress line, the For You badge, and the two-line Searches rows with Save. Not yet exercised: a physical phone, real provider media, scroll performance and TalkBack.

Recovery
