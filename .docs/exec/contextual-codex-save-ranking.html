Search-specific collections outrank large collections that share only common incidental tags.

Purpose

Save a yellow-tagged Search result and see a specialized yellow Codex before a much larger collection sharing common tags. Multi-tag searches reward all required groups co-occurring on each saved post. Normal order remains available through the existing icon.

Context and orientation

A query is the applied search, distinct from the editable draft. Required groups combine with AND; alternatives inside each group combine with OR. CodexSaveRelevance in app-logic currently sums raw overlap counts. CodexCollectionSource observes all local collection posts off Main only while the save sheet is open. TheoriaApp owns pending saves and ViewerSession retains transient launch information after navigation handoff.

Phases and work plan

  1. Capture origin: Search card actions snapshot applied query, Search Viewer launches retain it in ViewerSession. Other surfaces receive no unrelated global query. Carry snapshot through pending sheet state.
  2. Replace size-sensitive counts with normalized proportions. Complete query match fraction weighs 75%, average required-group match fraction 20%, incidental incoming-tag match fraction 5%. With no positive query groups, use incidental density alone. Duplicate post IDs and normalized tags count once. Empty collections return zero. All query groups must match on one post for complete credit; exclusions receive no positive ranking weight.
  3. Update focused app-logic ranking tests, source-flow integration tests, sheet score fixtures, and Viewer launch-context retention evidence. Record behavior in AGENTS.md. Run one bounded test/Detekt batch; repair only evidenced defects.

Errors retain existing zero-score fallback and normal stored order. Ranking never writes library order or requests provider metadata.
