Purpose · Context · Phases · Work plan · Validation · Living log · Recovery

Purpose / Big picture

Collect real history starting at upgrade, split foreground intervals at local midnight, and retain promoted post thumbnails even after upstream deletion or unlike. UI work belongs to the separate Claude checkout. No devices, production data, network analytics, sync, or remote likes/follows.

Context and orientation

core-data/src/main/kotlin/com/theoriacodex/data/repository/StatisticsRepositories.kt owns a JSON DataStore (atomic persistence). Its v1 file is statistics_store_v1.json. Repositories.kt declares the domain records and repository. app/src/main/java/com/theoriacodex/app/statistics/AppUsageTracker.kt accumulates monotonic foreground time, publishes live ticks, and flushes on transitions. app-logic/src/main/kotlin/com/theoriacodex/app/statistics/StatisticsProjection.kt exposes UI records. app/src/main/java/com/theoriacodex/app/settings/SettingsStatisticsSource.kt combines settled and live data.

A promotion means entering any Codex top-five opened/video/image list. Durable images must live outside general caches. Foreground time may exceed the sum of categories; preserve the difference for Other.

Phases

  1. Contract: commit defaulted history and nullable thumbnail fields; send SHA and exact shape to UI owner.
  2. History: additive persistence with v1 migration, local-date interval splitting, 400-day retention, live projection and backup compatibility.
  3. Thumbnails: cache on promotion/open when post data exists, copy local cached data first, reuse image stack, remove only after final demotion, isolate failures.
  4. Validate: focused behavior tests plus affected module host suites; update this evidence and commit. Send final head and results to UI owner.

Work plan

  1. Add DailyStatistic with LocalDate and default zero counters, StatisticsSummary.history default empty, and CodexPostStatistic.thumbnail default null.
  2. Extend statistics records and repository so event counters update their local day independently of lifetime. Share date split/merge logic between tracker persistence and live overlays. Do not write on ticks.
  3. Inspect profile backup codecs before modifying schema. Preserve all legacy counters and all-time values.
  4. Add private thumbnail file owner and dependency wiring, connect viewer post availability and usage promotion, and expose only local references to projection. Stats reads must never fetch.
  5. Cover midnight, foreground Other, migration, retention, promotion/demotion and failed fetch. Add changelog entries.

Validation and acceptance

From repository root, preflight Java/Gradle/Android SDK and cached dependencies, then run ./gradlew :core-data:test :app-logic:test :app:testDebugUnitTest --offline (adjust app variant to actual configured host lane). Expect host suites to pass. A v1 file retains every total and starts with empty history. Crossing midnight allocates exact elapsed milliseconds to both dates; ticks stay in memory. History retains today and previous 399 dates, oldest first, omitting inactive dates. Images survive cache clearing/unlike, disappear after final demotion, and failed fetches never reject a statistics mutation. No device installation or UI validation is authorized.
