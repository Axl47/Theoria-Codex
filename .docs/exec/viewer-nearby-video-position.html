Nearby Viewer video positions

Owner: Codex · 2026-10-22 · Status: complete (host validated)

Purpose · Context · Work · Validation · Log · Recovery

Purpose

Returning to a video within five post swipes in either direction resumes its last playback position in the current Viewer session. Positions beyond that moving window are discarded. Closing Viewer starts a new memory.

Context and orientation

app/src/main/java/com/theoriacodex/app/viewer/ViewerScreen.kt owns the session and post pager. ViewerMediaPage.kt and ViewerMediaContent.kt route media to ViewerVideoPlayer.kt. The video renderer currently remembers position locally and saves it when its player lease is released; removing its composition loses this value. ViewerMediaKey identifies a post and gallery index. The new ViewerVideoPositions.kt stores only timestamps, never players or media buffers.

Phases and work plan

  1. Add a plain Kotlin position cache and focused host tests in app/src/test/java/com/theoriacodex/app/viewer/ViewerVideoPositionsTest.kt. Retain current post and five neighboring posts per side; reject late writes for evicted posts.
  2. Remember the cache by Viewer session in ViewerScreen, update its window after composition, pass it through ViewerMediaPage and ViewerMediaContent, and read/write at player binding/release. Preserve explicit restart commands without replaying old commands when revisiting a video.
  3. Run the focused host test and Kotlin compilation, update CHANGELOG.md, and commit.

Validation and acceptance

From repository root run ./gradlew :app:testDebugUnitTest --tests '*ViewerVideoPositionsTest' :app:compileDebugKotlin --offline --console=plain. Expected: success. Host tests cover 1→2→3→2→1→3, exactly five neighbors, eviction at six, gallery identity and late writes. Manual physical-device check (not authorized or performed here): play three videos to distinct timestamps, swipe backward and forward, and observe resumed playback; travel six posts away and verify the expired video starts over. Host checks do not prove hardware playback.

Living log

Progress

2026-10-22: implemented the session-owned position cache, renderer wiring, and restart-serial handling. Added four focused host tests. Kotlin compilation and all four tests passed; no failures, errors, or skipped tests. Added the user-facing changelog entry.

Surprises

Restart commands use a cumulative serial and were applied on every player mount; revisits must not replay an old serial.

Decisions

Codex, 2026-10-22: use post distance rather than number of cached videos, matching five Viewer scrolls. Use per-gallery-item identity and session-local storage; no database or additional live players.
