Typed searched-tag suggestions

Status: implemented, in review Owner: implementation agent · Started 2026-11-17 · Branch feat/typed-tag-suggestions

Search's tag composer leads with tags the user searched before (up to three) and saved tags. Until now only plain general tags were remembered, so nhentai or Hitomi artists, groups, parodies, characters, languages and Hitomi female:/male: tags never came back as suggestions. After this change every searched term is remembered with its type, suggestions follow the effective scope, and tapping one adds the term with its type intact.

Context

Terms. A search term (SearchTerm) is a value plus a facet (TAG, ARTIST, CHARACTER, SERIES, GROUP, TYPE, LANGUAGE) and an optional source namespace (for example nhentai's artist, Hitomi's female). A scope (FacetedSearchScope) is the tag type the composer is aimed at; All has no facet. The effective scope is the picked scope unless the typed input starts with a prefix such as artist:, which overrides it. A general tag is a TAG term with no namespace or the tag namespace (nhentai and Hitomi spell their Tag scope that way).

Before. SearchCoordinator called statisticsRepository.recordSearch(sources, tags) with only portable general tags (TAG, no namespace). Counts live in LifetimeStatistics.searchesByTag (core-data Repositories.kt), persisted in the statistics DataStore JSON (StatisticsStoreRecord, file statistics_store_v1.json) and in profile backups, which serialize the same record. rankSearchedTags (app-logic TagSuggestionRanking.kt) returned strings. The composer (app/.../search/SearchComposerModel.kt) showed saved and searched rows only in general scopes and added them as plain tags.

Unified mode. Unified searches run only portable general terms (Query.normalizedForMode drops the rest), has no faceted scopes (SearchCoordinator.supportedSearchScopes returns none), and blocks typed prefixes. So Unified suggests only portable general history; typed history would be dropped on run.

Decisions

DecisionWhy
In memory, search counts become Map<SearchedTagKey, Long> where SearchedTagKey(source, term: SearchTerm). Watched-tag counts keep StatisticsTagKey.The term already carries facet and namespace; a dedicated key keeps watched post tags (always plain strings) unchanged.
On disk, portable general counts stay in searchesByTag records exactly as before; every other term goes to a new searchesByTypedTag list with facet and sourceNamespace. No schema version bump.Old stores and old backups read unchanged. An older build reading a newer store or backup ignores the unknown list instead of misreading artists as general tags. Records with an unknown facet are skipped, so a future facet cannot break decoding.
Recorded terms are the query's required terms that actually ran: query.portableTermsForUnified().includeTerms. Excluded terms are not counted (unchanged).A typed term in a Unified draft never runs, so it should not be remembered.
The Recents seed runs once more for terms the first seed skipped (everything but portable general tags), tracked by a new searchesByTypedTagSeeded flag.Recents store full queries, so recent artist searches become suggestions right after upgrade. Before this change typed terms were never counted, so seeding cannot double count; merging with max keeps the step idempotent, like the original seed.
Saved tags stay general-only.No typed tag can be saved today: the composer's tag menu offers Save only for general tags (ComposerSavedTags.canSave), and post info saves plain strings. There is no typed saved data to suggest. Adding typed saving is a new feature across the saved-chip UI (how a typed chip reads), repository API, normalization and backup validation, and needs its own design pass. The composer filters saved entries through the same scope check as history, so typed saved tags would work there without further change.
General tags form one type whether spelled with no namespace or tag; every other facet/namespace pair is its own type (SearchTagType in core-domain). A scope accepts a term when it is All or has the same type.Matches PR #138, where tag: counts as general, and the post-info notion of a general tag. It now also applies to the picked Tag scope of nhentai and Hitomi.
In the All scope, typed history shows beside general history with its type in the row meta (for example "Artist"), the label provider faceted rows use. General history rows keep an empty meta.Same look as the provider's faceted rows; the history icon still marks the row.
Tapping a history row adds its stored term (facet and namespace intact): Required adds it, Excluded excludes it, an Alternative group takes it only when the type matches (general joins general, taking the group's spelling).Same rules as provider faceted rows and the draft reducer's group invariant.
