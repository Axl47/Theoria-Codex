Automatic CJK OCR translation overlays

Add opt-in, zero-touch Japanese, Chinese, and Korean text detection to static Viewer images. Enabled on-device OCR recognizers run in a metadata-first sequence after the current image becomes visible; detected phrase regions become tappable highlights, and tapping one sends only that phrase to the self-hosted Hy-MT2 service at translate.axor.dev for an English translation.

Purpose / Big Picture

After this work, a user can open Settings, turn on automatic Viewer text translation, acquire the Japanese, Chinese, or Korean OCR models, and enable the ready languages they want considered. Opening a static Viewer image then starts OCR in the background without a separate mode or tap. If CJK text is found, subtle boxes appear over detected phrases. Tapping a box shows a small anchored loading surface immediately; that same surface changes to the English response from translate.axor.dev and dismisses a few seconds after success.

The feature remains opt-in and static-image-only. OCR uses on-device ML Kit after its optional model is present. Translation sends only the exact tapped phrase plus its source code and English target over HTTPS to the user's self-hosted Hy-MT2 gateway; image pixels, media URLs, post identity, taxonomy, headers, and account data remain on-device. Undownloaded OCR models are never fetched merely by opening Viewer, and animated images, GIFs, videos, and Pixiv Ugoira are not scanned in this version.

The observable result is not “an OCR API was added.” It is: settings accurately show what can run, Viewer remains immediately interactive, phrase boxes stay attached to the image while zooming and panning, a tapped box shows deterministic loading/success/failure feedback, and rapid navigation cannot publish stale boxes or translations onto another image.

Context And Orientation

CJK means the three source-script families in scope: Japanese, Chinese, and Korean. An OCR recognizer converts pixels into text plus image-space geometry. A region is one nonblank ML Kit text block retained as a tappable phrase. A normalized polygon stores each region corner as fractions from 0 to 1 of the OCR bitmap width and height, allowing the same result to be mapped onto different Viewer sizes. An OCR module is the optional Google Play services recognizer downloaded from Settings. The translation server is the user's CPU-hosted tencent/Hy-MT2-1.8B-GGUF:Q4_K_M model behind a narrow compatibility gateway; it receives phrase text only after a highlight tap.

Existing flow

ViewerRoute creates a navigation-scoped ViewerViewModel, consumes immutable Viewer state, and passes renderer configuration into ViewerScreen. Static images are loaded with Coil inside a centered, padded box using ContentScale.Fit. The image receives the current ViewerTransformState through one graphicsLayer; a separate full-screen gesture layer owns single tap, double tap, long press, paging, zoom, and pan. This means OCR is not a new navigation feature, but it must integrate with two established owners: the route owns cancellable background work, and the renderer owns exact image geometry and gesture hit testing.

Settings are durable AppSettings values in core-data. SettingsViewModel observes that repository for rendering and routes typed actions back to repository methods. Section expansion is separate UI-restore state. The Settings ViewModel receives a SettingsEntered action when the Settings tab becomes active and again when the app resumes on that tab, allowing OCR and translation resources installed in an external store/settings surface to refresh without adding startup work.

Automatic recognition

  1. Do nothing when the global setting is off, there are no enabled-and-Ready languages, the current media is animated/video, or the image has not rendered successfully.
  2. Analyze only the currently selected static image after it is visible. Do not pre-scan adjacent Viewer pages.
  3. If post resolution is still running, retain the image-ready signal and wait for resolved or terminal metadata so the typed language facet can be considered first.
  4. Build the candidate list from languages that are both enabled in Settings and Ready according to the live model manager.
  5. If post.taxonomy has a supported SearchFacet.LANGUAGE value, try that language first. Then append every remaining candidate in fixed Japanese → Chinese → Korean order.
  6. Run candidates sequentially, never concurrently. A failed recognizer does not prevent the next candidate. Stop at the first recognizer returning at least one valid region containing target-script evidence; Latin-only watermarks do not count as success.
  7. If all candidates return no accepted regions, publish no boxes and no user-facing error. Cache that negative result for the current media identity.

Recognized metadata spellings must be normalized case-insensitively. At minimum map japanese/ja, chinese/zh/zh-hans/zh-hant, and korean/ko. Only typed language facets participate; a general tag such as “chinese dress” must never select the Chinese OCR model.

After Japanese block normalization, group only tall columns that are horizontally adjacent, vertically overlapping, similar in width, and whose union remains compact. Read the grouped columns from right to left, remove whitespace inside each vertical column, and use the union rectangle for the highlight. Punctuation does not end a compact group because one manga bubble commonly spans multiple punctuated columns. Horizontal Japanese plus all Chinese and Korean regions remain unchanged. These conservative geometry bounds deliberately leave ambiguous text fragmented instead of merging across speech bubbles.

Durable settings versus device state

Add ViewerOcrLanguage with exactly JAPANESE, CHINESE, and KOREAN. Extend ViewerSettings with automaticTextTranslationEnabled: Boolean = false and enabledOcrLanguages: Set<ViewerOcrLanguage> = emptySet(). The old app behavior therefore remains unchanged after update. Serialize the set as stable enum-name strings and ignore unknown future names on decode.

Do not persist Downloading, Ready, Failed, or Unavailable. Those states belong to OcrLanguageModelManager because Google Play services can add or remove a module independently of the Settings file. Settings combines durable intent with current capability for presentation. Viewer intersects the two again immediately before analysis; it never trusts a stale Settings screen snapshot.

Pure policy in app-logic

Create Android-free types such as NormalizedPoint, NormalizedPolygon, ViewerOcrRegion, and ViewerOcrCandidate. Keep the following functions deterministic and unit-tested in app-logic:

  • metadataOcrLanguage(taxonomy): map only typed language facets.
  • orderedOcrLanguages(metadata, enabled, ready): metadata match first, then Japanese, Chinese, Korean without duplicates.
  • containsScriptEvidence(text, language): require kana or Han for Japanese, Han for Chinese, and Hangul for Korean; reject Latin-only output. Document that Han-only unknown metadata follows the requested Japanese-first fallback and may occasionally be misclassified.
  • normalizeOcrPolygon(points, bitmapWidth, bitmapHeight): clamp finite values to 0–1 and reject degenerate geometry.
  • selectOcrRegionAtTap(...): invert Viewer scale/pan and fitted-image offsets, use a small accessibility hit expansion, and choose the smallest/closest overlapping region deterministically.
  • placeTranslationCard(...): below-first, above-fallback, viewport-clamped screen-space placement.

Android model and inference layer

Use unbundled Text Recognition v2 artifacts for Japanese, Chinese, and Korean. A shared factory is the one mapping from language to its matching TextRecognizer options. OcrLanguageModelManager creates a recognizer only for the duration of an availability/install operation, queries or installs its optional module through ModuleInstallClient, then closes it after the Task and listener complete. The manager exposes typed state, coalesces duplicate requests, and unregisters install listeners. A fake gateway covers deterministic tests without Google Play services.

ViewerOcrTranslationCoordinator receives the currently displayed candidate URL and source. It uses MediaRequestFactory so Pixiv and other protected headers remain request-scoped, disables hardware bitmaps, and requests a fit decode bounded to a 2048 × 2048 box. The resulting bitmap dimensions are the geometry authority passed to InputImage.fromBitmap. Never decode the full original page into a second unbounded ARGB bitmap and never recycle a Bitmap owned by Coil.

Each accepted ML Kit TextBlock becomes one phrase region. Prefer cornerPoints; use the block boundingBox only when corners are absent. Retain trimmed block text without removing Japanese/Chinese/Korean spacing semantics. Filter blank, degenerate, and Latin-only blocks. This first version does not attempt speech-bubble segmentation, sentence parsing, furigana removal, or cross-block context.

Translation uses English as the target on every Android version in scope. Build a form request containing only q, source (ja, zh-Hans, or ko), target=en, and format=text; post it to https://translate.axor.dev/translate on an IO dispatcher; reject cleartext URLs, phrases over 1,000 characters, non-success HTTP status, malformed/blank results, and responses over 64 KiB. Connection and read waits are bounded. Cache successful translations by source language plus exact recognized text in a small in-memory LRU. Do not persist source or translated text.

Navigation-scoped transient owner

Do not add OCR regions or translation text to durable ViewerUiState or Saved State. Create a parallel navigation-scoped ViewerOcrTranslationViewModel, following the existing specialized MediaDurationRouteViewModel precedent. Its active identity contains ViewerSessionIdentity, ViewerMediaKey, loadGeneration, and the displayed candidate URL. It holds only the current presentation state plus a bounded LRU of completed positive/negative analyses.

  • Selection or session change immediately clears visible regions/card and cancels the owner’s current coroutine.
  • Every callback verifies the complete identity before publication because an ML Kit Task may finish after coroutine cancellation.
  • Only one OCR analysis and one translation are current at a time.
  • A successful positive analysis is retained for the canonical media when a higher-quality URL replaces a same-aspect candidate. A negative result may retry once on a later quality-upgrade URL; it must not loop between fallbacks.
  • Changing the global toggle, enabled-language set, or Ready-language set invalidates the applicable analysis key and reconciles once.
  • Feature disable clears presentation immediately and schedules no further work.

Renderer and gesture integration

Extract static image plus highlight drawing into one transformed child so both receive exactly the existing ViewerTransformState. Keep the loading/translation card as a sibling outside that graphics layer. The existing full-screen detectTapGestures remains the single tap owner: on a single tap it first asks the OCR hit-test policy for a region. If a region is returned, dispatch RegionTapped and do not toggle chrome; otherwise preserve the current chrome toggle. Double tap, long press, horizontal navigation, and pinch/pan behavior remain unchanged.

AsyncImage.onSuccess should publish an image-ready event only for the current static media page. Include displayed candidate URL and the rendered drawable’s positive intrinsic dimensions. A LaunchedEffect keyed by image readiness plus resolution state replays this signal after authoritative post metadata arrives; it must not rely on an image reload to restart analysis.

Performance and memory acceptance

  • OCR starts only after the current AsyncImage reports success, so it is absent from Viewer first-render work.
  • No OCR input bitmap exceeds 2048 pixels on either axis; worst-case 2048 × 2048 ARGB storage is approximately 16 MiB before decoder overhead.
  • Only one current-media OCR analysis and one translation request are active. Adjacent pages are not pre-scanned.
  • Main-thread trace evidence contains only identity/state dispatch; bitmap conversion/normalization beyond lightweight geometry and all blocking waits remain off the main thread.
  • For ten representative page changes, record per-language recognize duration, translation latency, and heap before/after leaving Viewer. There is no monotonic heap growth and no duplicate HTTP request is created by recomposition.

Surprises And Discoveries

  • The existing Viewer applies zoom/pan directly to each media renderer while taps are owned by a separate full-screen gesture layer. Image and highlights therefore need a shared transformed wrapper, while hit testing must invert the transform before choosing a normalized region.
  • The Viewer may display a progressive candidate and upgrade it after first success. Positive OCR should remain stable across same-media quality upgrades; only a prior negative may retry once.
  • Posts already carry source-aware typed language taxonomy for Hitomi and NHentai, with values including Japanese, Chinese, and Korean. This is a stronger selector than scanning general tags and requires no Post schema change.
  • The Settings owner is activity-retained. It refreshes readiness when its tab becomes active and when the app resumes on that tab, so external language-pack installs appear immediately without increasing ordinary app startup work.
  • A Viewer can be restored before Settings is visited after process restart. Viewer entry therefore performs a read-only model availability refresh so previously downloaded/enabled OCR resumes; this query never requests a download.
  • ML Kit's on-device Translation API requires Google Translate attribution, while the linked branding rules prohibit displaying that trademark in an interface containing adult content. Android's neutral API was attempted instead, but Samsung device acceptance proved its service unusable for arbitrary third-party text. Self-hosted Hy-MT2 now provides the translation boundary; ML Kit remains the on-device OCR provider.
  • The current Settings DataStore serializer rejects any version other than 3 before migrations can transform it. Additive defaulted fields should retain schema version 3 unless the storage migration architecture is separately changed.
  • Concurrent whole-set Settings writes could drop a language when a model download completed beside another toggle. Moving one-language enable/disable into the repository makes each mutation atomic and preserves both intents.
  • The hotspot gate rejected the first integrated shape because ViewerScreen.kt grew beyond its frozen budget. Extracting the existing top chrome/playback/actions surface into ViewerChrome.kt restored the budget and made its action groups independently analyzable.
  • The first release JSON check exposed an existing keep rule that still named HitomiPageToken as a nested HitomiSourceAdapter class after it had moved top-level. Correcting that exact class name made both release variants verify all 241 durable fields.
  • Read-only SM-S926U logs proved Japanese, Chinese, and Korean OCR were already installed as shared Google Play-services Dynamite modules. The same device exposes Samsung's on-device TranslationService, but its language packs are independently managed; OCR readiness does not imply a source-to-English translator can be created.
  • Samsung's general translation settings listed only installed/advertised languages and did not provide a complete download catalog. Its bidirectional English pair packages are independently visible as enja, enzh, and enko, and Galaxy Store accepts a direct package-specific product intent.
  • Installing every Samsung pair package does not make Android's public TranslationManager usable for arbitrary text. The Samsung service acknowledges session creation but its bind callback performs no translator initialization; the actual translator is created only as part of Samsung's chat-room feature lifecycle.
  • LibreTranslate quality drops sharply when a vertical Japanese sentence is split into independent short columns. ML Kit's block boundary is therefore not always a semantic phrase boundary; conservative post-OCR spatial grouping provides more context without changing recognizer selection or the translation protocol.
  • The translation-host capacity check exposed an unrelated publicly published, unauthenticated Redis port in the stopped n8n autoscaling deployment. Attackers had replaced Redis PID 1 and were running a miner as /tmp/postgresql. The exact container and orphaned process tree were removed, ports 6379/5432 are closed, and that n8n Compose project must remain stopped until its source definition removes public database ports and recreates its disposable Redis volume.
  • The VPS could not anonymously pull the documented public llama.cpp GHCR image. Building a minimal runtime from the official b10775 Ubuntu release archive, with its observed SHA-256 pinned, preserved upstream provenance and avoided an untrusted mirror.

Idempotence And Recovery

All host-side Gradle tests, compilation, Detekt, R8 JSON verification, HTML validation, hotspot audit, and diff checks are safe to rerun. OCR module install and translation-model preparation are designed to be idempotent: availability is checked first, duplicate per-language operations are coalesced, and an interrupted install is rediscovered through live status when Settings is reopened.

No database migration, file deletion, cache clear, production-package operation, or model removal is planned. Settings additions are backward-compatible defaults in the existing schema version. If a partial settings patch cannot decode the current store, stop and repair conversion/tests; never delete settings_store_v3.json as recovery.

The Hy-MT2 rollout is recoverable without an Android release because the public form/JSON contract did not change. The Dokploy working directory retains docker-compose.libretranslate.yml; stopping the two new services, restoring that file as docker-compose.yml, and starting its libretranslate service restores the prior backend. Do not delete theoria-hymt2-models unless intentionally reclaiming the downloaded model. The detached n8n Redis volume remains quarantined because permanent deletion requires explicit user authorization; never restart that project until its source Compose removes public Redis/PostgreSQL ports and provisions a clean Redis volume.

If interrupted during implementation, inspect this plan, working_list.md, and git diff. Resume from the first unchecked Progress item, re-run that phase’s focused command, and update the plan immediately with actual results. If a real recognizer integration proves unavailable on supported Google-certified devices, keep the interfaces and Settings contract but do not ship a fake Ready state; record the API/device evidence and decide separately between bundled models and removing download management.

Before any device-affecting recovery command, repeat the Debug package-identity proof. Never use adb uninstall, pm clear, signature-mismatch reinstall, or a production application ID.

Appendix: Evidence, APIs, And Implementation Notes

ML Kit facts used by this plan

  • Text Recognition v2 has distinct Chinese, Japanese, and Korean Android recognizers; it returns blocks, lines, elements, symbols, bounding boxes, corner points, and confidence/rotation metadata where available.
  • The unbundled Play-services recognizers add about 260 KB per script architecture to the app and download their models dynamically. The bundled alternative adds about 4 MB per script per architecture.
  • ModuleInstallClient can check optional-module availability, request immediate installs, expose progress, and report errors. Requests made to an unbundled recognizer before its module finishes downloading can produce no results, which is why Viewer must use only Ready models.
  • The gateway exposes the retained POST /translate contract for ja, zh-Hans, and ko to en. It converts only those fields into a manga-aware Hy-MT2 chat prompt, caps output, serializes inference, and persists the Q4 model cache outside the container.

Primary references: ML Kit Text Recognition v2 for Android, Google Play services ModuleInstallClient, Tencent Hy-MT2-1.8B, official Hy-MT2 GGUF release, and llama.cpp server. The facts needed to execute the plan are summarized above so the file remains useful offline.
