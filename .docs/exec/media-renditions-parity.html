Media renditions parity

Status: in progress · Owner: Claude (orchestrator), Sonnet subagent (implementation) · Started 2026-11-11. Covers audit findings A3 and A4 from the cross-source performance parity audit.

Purpose / Big Picture

"Show a lighter image first, then the original" is today switched on per source by a hand-kept list in app/src/main/java/com/theoriacodex/app/media/PostMedia.kt (QUALITY_UPGRADE_IMAGE_SOURCES, plus a separate rule34.xxx special case). The list exists because ImageRef.progressiveUrls means two different things: on Pixiv and the boorus it holds lighter renditions (samples); on nhentai and Hitomi it holds equivalent copies of the same full-size file (mirrors, other formats, other CDN shards). Shared code cannot tell them apart, so every new source starts without the optimization and parity drifts.

After this plan: an ImageRef says which URLs are lighter renditions and which are equivalent copies. The Viewer upgrades from a lighter rendition to the original for any source whose media offers one; feed cards upgrade up to the largest lighter rendition for any source unless that source explicitly opts out with a stated reason. Gallery pages (nhentai, Hitomi) show their small page thumbnail while the original loads, and Viewer neighbor prefetch warms those thumbnails first.

Work Plan

  1. Domain. In Post.kt add val fallbackUrls: List<String> = emptyList() to ImageRef with a KDoc: equivalent copies of url, tried only when it fails, never shown as a lighter step. Tighten the progressiveUrls KDoc: lighter renditions of url, lightest first, shown before it.
  2. Persistence. Add an optional fallbackUrls field next to every persisted progressiveUrls (Gson records use @field:SerializedName and nullable defaults, so old JSON decodes to null). Write one helper in core-data that, on decode, when the stored field is absent (null) and the post's source is SourceKey.NHENTAI or SourceKey.HITOMI, moves progressiveUrls into fallbackUrls. This source check lives only in the legacy decoder and its comment says so. PostMergePolicy merges fallbackUrls the way it merges progressiveUrls. Portable/backup/share codecs carry the field and apply the same legacy rule when reading.
  3. Producers. nhentai page refs: fallbackUrls = imageUrlCandidates(...), progressiveUrls empty. Hitomi: full-size format/shard candidates go to fallbackUrls; thumbnailFirst keeps the thumbnail as url for card previews and moves the other thumbnails and the full-size locations to fallbackUrls. Update the Hitomi health probe to read both lists.
  4. Delivery plans. In PostMedia.kt, orderedImageLocations becomes lighter renditions, then url, then fallbackUrls (with urlFirst keeping its current meaning for the first two groups). Candidates from fallbackUrls are always FAILURE_FALLBACK. A location is a quality upgrade when it is url or a lighter rendition after the first candidate and the ref has lighter renditions; no source list. Keep the existing "cards stop below the original" rule (feedOriginalLocations). Add cardsStayOnPreview: Boolean = false to SourcePresentation in app/.../source/SourceMetadata.kt, set it only for rule34.xxx with the reason from commit 76a5f8fa (every card would otherwise download a sample), and have previewMediaDeliveryPlan read it. Animated-image locations (animatedImageLocations) also take animated fallbackUrls. Update hasUsableViewerMedia and any other consumer that treats progressiveUrls as "somewhere to load from" to include fallbackUrls.
  5. A3. viewerLoadingPreviewLocation: for a gallery page after the first, prefer media.thumbnailUrl, then progressiveUrls.firstOrNull() (still cache-only). In ViewerPlatformPrefetcher.prefetchViewerMedia, for IMAGE media with a distinct remote thumbnailUrl, warm the thumbnail disk-only (existing diskWarmOnly()) before the original request.
  6. Keep comments in sync; delete comments that describe the removed allow-list.

Out of scope: video renditions, Gelbooru URL normalization, Hitomi's WebP overview special case. Do not touch GelbooruSourceAdapter.kt (A2 already landed there) or the files owned by the parallel tasks: SearchResultCard.kt, search feed files, ViewerViewModel.kt, ViewerRouteWorkflow.kt, SearchCoordinator.kt, CustomSiteHttpClient.kt, DefaultSourceHttpClient.kt, the ugoira and video branches of ViewerPlatformPrefetcher.kt, and nhentai's tag cache.
