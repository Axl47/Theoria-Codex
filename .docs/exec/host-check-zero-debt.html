Host check zero debt

Purpose / Big Picture

The host checks passed partly because a Detekt baseline hid findings and because warnings do not fail a build. This work makes the checks mean what they say: every Detekt baseline is empty, every warning a host check prints is fixed or explained, and app behavior does not change. Afterwards, a new finding is visible the moment it appears, because nothing is hiding it.

Current Status

Implemented and passing every host check. Not yet run on a device. Next action: the owner authorizes a debug install on the S24, or tries the Viewer, Search and tab switching there, and a physical-device performance run decides whether the recomposition changes held up.

Context And Orientation

A "host check" is one that runs on the development machine without a device. .github/workflows/verify.yml defines them: module tests, assembling Debug and Release, Android lint, the hotspot budget (scripts/check_hotspots.py, reading config/quality/hotspot-budgets.json), the jscpd duplicate audit, Detekt, Kover coverage, and changed-line coverage.

"Detekt" is the static analyser. Its baseline files in config/detekt/ list findings to ignore. Only two rules produced findings here: LongMethod (over 60 lines) and CognitiveComplexMethod (over 15).

A "recomposition" is Compose re-running a composable because something it read changed. Compose can skip a child whose inputs are unchanged, so creating a new object on every run can make children re-run needlessly. Much of the care in this work is about not doing that.

Before this work, removing the baselines showed 19 findings across 11 functions, all in :app. The worst were TheoriaAppContent (1464 lines, complexity 526) and ViewerScreen (580 lines, complexity 271). The other baseline entries were stale.

Surprises And Discoveries

  • Most baseline entries were stale. Their functions had already been refactored, and nothing flags an entry that no longer matches.
  • Detekt passing said little: the hotspot budget was already failing on TheoriaApp.kt by 32 lines.
  • Bundling feed values into a new object on every composition would have made every visible card recompose. The bundles are remembered on their inputs for this reason.
  • Passing JVM flags based on Gradle's own JDK broke :app-logic:test, whose toolchain is older and rejects the flag. The check now reads each test task's JVM.
  • CodexLibraryScrollReturnTest looked like a slow-machine timeout, but it passed at eight times CPU load. A probe showed the wait normally takes 0 ms and that every thread was idle when it failed. Its wait condition never read the Compose tree, so nothing drained the main looper when settings answered after the first idle. A longer timeout would have changed nothing. Forcing a 500 ms settings delay reproduced it every time.
  • PostTagActionTypedCountsTest scrolled to counts that load on real dispatchers, which waiting for Compose to go idle does not cover. The hunt for the first flake surfaced it.
  • Declaring Detekt's internal friendPaths as a task input did not clear the artifact-transform deprecation, so that change was reverted. Trying AGP 9.5.0 removed AGP's own setVisible warning, but Kover and Detekt still emit it.
  • Several screens passed local function references such as ::clearFilters. The Compose compiler can memoize those with their first captured values, as a comment in ViewerScreen already warned. They are lambdas now, so undo always restores the current filters.

Idempotence And Recovery

Each phase is its own commit, so a phase can be reverted alone. Re-running any check is safe. To see the real findings if a baseline ever regains entries, empty the CurrentIssues element in config/detekt/baseline-*.xml, run the Detekt tasks, and restore with git checkout -- config/detekt.
